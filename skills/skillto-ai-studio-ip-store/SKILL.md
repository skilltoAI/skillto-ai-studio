# Skillto-AI-Studio · 角色与场景库

这是 `skillto-ai-studio` 的子技能。由父技能路由至此后，按下文采集、角色卡、场景图和两张总表的流程执行；需要报表展示时使用同级 `skillto-ai-studio-table`。技能名称中的 `IP-store` 只是库的名称，内容仍统一称为“角色”。

视频可以出现婴幼儿、成年人、宠物、其他动物、虚构生物或群像；统一称为**角色**，不用“IP”代指角色。每次分析服务于以后选角色、选场景。库只有两张持续维护的总表：`research/ip-scene-library/角色卡库表.md` 与 `research/ip-scene-library/场景库表.md`。单条视频目录保存源视频、关键帧、生成图和一份采集/分析记录，**不要再创建或更新逐视频角色表、逐视频场景表或同名副本**。既有逐视频表仅是历史资料；将可核实的信息迁入总表后，不再把它们当作库入口。

**默认交付是原视频角色的忠实采集与角色卡。** 保留角色在视频中的原型、物种/类型、年龄段（可辨时）、脸与身形比例、毛色/肤色/花纹、发型/毛量、服饰饰物、道具、动作关系和视觉风格。不要擅自换成另一只动物、另一张脸、另一种毛色或画风。背景统一为 `#888888` 仅是角色卡排版要求，不改变角色本身。用户明确提出原创改编时，才另建“原创候选”卡与独立 ID；它不能替代原角色卡。

## 1. 采集与逐帧核对

**视频文件是入库前置条件。** 用 `scrapling` 采集用户给出的短视频链接中的**视频媒体**，验证媒体时长和画面后，才从该文件抽帧、分析角色与场景、生成图并更新总表。网页截图、播放器截图、页面缩略图、同账号其他视频和标题都不能替代原视频文件或充当“视频原图/卡图垫图”。只有网页截图时停止入库并记录阻碍。

1. 记录原视频 URL、作者、采集时间、标题和页面流量快照。按已安装的 `scrapling` skill 执行 `doctor`，先静态 `discover`，再按需动态浏览器发现、`formats`、`download`。优先保存公开播放器的完整媒体响应。若独立 CDN 请求被拒而授权浏览器可播放，可由 Scrapling 的浏览器会话录制**完整 `<video>` 元素流**为视频文件；明确标为“播放器转码录制”，不得称作原站原始编码文件。不得绕过登录、验证码、DRM 或速率限制。报告中不保留 cookie 和带时效签名的媒体链接。
2. 在工作区保存视频并用 FFmpeg / ffprobe 核实文件非空、可解码、时长与播放器相符、视频流/音轨信息；避免将页面附带的无关短媒体误认为目标视频。**只从已验证的视频文件**抽取带时间戳的关键帧，覆盖出场、正/侧/背或三分之二视角、动作转折、表情眼神、场景转换。缺失的视角写“原片未展示”，不能把生成视图说成实拍帧。若无法取得可验证视频，记录阻碍，未知字段保持未知，不生成声称“基于原片”的角色卡或场景图。
3. **先判定原片视觉风格与角色原型，再制作角色卡**：写明它是照片级实拍/写实 CGI、半写实 3D、卡通 3D、2D 插画、动漫、定格或混合风格；逐项记录角色可识别的外貌、体态、配件和道具，并用画面证据说明纹理、皮肤/毛发、光学景深、镜头运动、色彩、比例和渲染方式。无法确定制作技术时只写“视觉呈现为……”，不要推断拍摄或生成手法。

## 2. 角色分析与卡图

1. 给每个可辨角色稳定 ID，注明类型（婴幼儿/人/宠物/动物/虚构生物/群像）、物种或年龄段仅在画面支持时填写。写**角色简介、角色人设**：前者说明视频中的功能和吸引点，后者分开写可见行为与创作推测，不推断真实人物的性格或身份。
2. 分别分析**外形外貌、表情、动作、眼神**的“流量密码”，每项附时间戳和画面证据。人类可分析脸形、五官比例、发型、服装和体态；宠物/动物改分析物种、耳鼻口吻、眼形、毛色花纹、毛量、尾巴、躯体轮廓、饰物与步态；婴幼儿避免推断超出画面的心理。眼神无法辨认时标“不可判”。单条视频的播放、点赞、评论和分享只表示整片表现，不能证明某个角色设计的因果效果。
3. 如果角色属于第三方，将源角色、原帧和忠实还原的源角色卡标为**仅分析参考**，记录来源与权利状态；制作分析卡不代表获得商业复用权。**不能因为第三方身份而把采集对象改成陌生原创角色。** 用户明确要求原创改编时，另建独立 ID、名字和 brief，清楚区分源角色卡与原创候选卡，并记录设计差异；设计审查不等于法律许可。
4. **保留原角色原型、视觉媒介与质感。** 源角色卡以原片可见身份为准：脸形、五官/眼形、体形比例、毛色/肤色及花纹、尾耳、服装饰物和道具应与证据帧一致；跨视角不得漂移。照片级/写实原片保持相同照片级/写实表现、毛发或皮肤细节、光照与镜头质感；卡通/插画原片匹配原媒介与造型语言。不能把源角色变成新物种、改变胖瘦或年龄、换毛色花纹、移除标志性配件，也不能把实拍改成动画或反之。用户明确要求改动时，将改动另标为改编，不冒充源角色还原。
5. **先选原视频角色垫图再生图**：从已保存的原片关键帧中挑至少一张清楚的角色原图，优先补充正面/侧面、动作起势、转折、高潮和表情眼神帧；逐张记录时间戳及用途。使用内置 `image_gen` 的 `referenced_image_paths` 传入本地原帧，把它们明确标为**源角色身份、造型、风格、动作与情绪的共同约束**；生成各视角时持续使用同一组身份锚点。不得只用文字 brief 或无关图片生成后称其为“基于原视频”。原片没有的视角或动作须标为 AI 补全，不冒充实拍证据；补全仍要保留可见原型。
6. **源角色卡成品格式**：一张卡应同时包含①同一角色的全身正面、90°侧面、背面三视图；若原片中跳舞，三视图使用同一舞蹈关键姿态，若没有跳舞，保留其原本动作/道具关系，不强行设计舞姿；②至少三个原片中可见或有明确依据的动作关键帧（起势、记忆点/高潮、收势）；③至少四格原片可辨的面部表情与眼神，无法辨认时标“不可判”，可做明确标注的 AI 补全但不得虚构成原片事实。各面板的身份、服饰、毛纹、体型、道具一致。原创动作仅在用户要求的原创候选卡中出现，不能塞进源角色卡冒充原片动作。群像关系是钩子时可另补群像卡。
7. **统一背景色为纯色 sRGB `#888888`（RGB 136,136,136）**：最终角色卡每个面板的背景与面板间隙都用这一精确色号；不得有原场景、道具布景、纹理、渐变、光晕、景深背景、白底或近似灰。可让 `image_gen` 先生成透明背景角色素材，再放到精确 `#888888` 画布排版；不能只在提示词写色号而不检查成品。角色本身保持原片的照片级/卡通等视觉媒介，灰背景不等于改变角色风格。
   **历史卡复核例外**：若既有卡已具备源角色一致的正/侧/背三视图与表情图，唯一缺陷只是背景色，则保留原图并记录背景待统一，不为换背景重生成。缺三视图、缺表情图或角色原型/风格与原视频不符的旧卡必须重制。新生成或重制的卡仍须使用精确 `#888888` 背景。
8. 角色卡生成可分为“原型锚点→三视图→动作序列→表情眼神→统一排版”多步；每一步沿用同一源角色的原帧和身份锚点。保存最终卡、使用过的源帧路径、提示词、原型核对与验收记录到工作区。用户要求原创改编时另存差异化 brief。源角色分析卡与原创候选卡须分别标注；只有通过下述验收的最终卡才能填入对应行的“角色卡图片”，未通过时标“待重制”，不得拿原帧或单张头像冒充成品角色卡，也不得以原创候选卡填充源角色行。

每次调用 `image_gen` 时把以下约束写进实际提示词，而不只写在分析记录里：

```text
垫图：列出原视频角色关键帧的本地 path、时间戳和参考用途；调用时作为 referenced_image_paths 传入。
角色：按源帧锁定原角色物种/类型、脸与身形、毛色/肤色/花纹、服饰饰物、道具和视觉风格；保留情绪弧线与已观察到的表演机制。不得擅自重设计原型或改变画风。
交付版式：同一源角色的正面/90°侧面/背面全身三视图 + 原片动作关键帧 + 至少四格可辨表情眼神；原片跳舞才用舞蹈关键姿态，原片未跳舞就保持原有动作与道具关系；所有面板身份一致。
背景：最终成品每个面板和间隙均为纯色 sRGB #888888 / RGB(136,136,136)，无原场景、纹理、渐变、阴影或近似灰。
真实性：来源帧同时约束角色身份、原型、动作、情绪和风格；原片未展示的视角或细节明确为 AI 补全，不能把补全说成原视频实拍。原创改编须用户明确要求并另建卡，不覆盖源角色卡。
```

## 3. 场景分析与图像

1. 选清楚的原帧，记录地点线索、机位/景别、可见的主光/补光/轮廓/背景光、色彩和后期线索。将观察与建议的复刻手法分开写。
2. 用 `image_gen` 去除角色，保持透视、家具、道具、阴影和照明，生成 AI 空场。再做“原帧 / AI 去角色”并排对比并明确标注两侧。不能把空场称作未修改的原视频画面。
3. 场景是否能直接用于新视频单独标注。第三方原片场景的去角色图默认是构图/布光参考；若要推荐为制作资产，应确认授权或另行生成独立场景。

## 4. 只维护两张跨视频总表

在 `research/ip-scene-library/` 维护且只维护：

两张总表的第一列统一为**五位序号**：角色用 `C` 加四位数字（`C0001` 起），场景用 `S` 加四位数字（`S0001` 起）。两类分别递增、分别唯一。序号是记录的稳定引用：新行取该表当前最大序号加一，排序、改名、更新、删除或迁移时不得重排或复用旧号；原有角色 ID / 场景 ID 保留在第二列。

- **`角色卡库表.md`**：每一行先记录一个源角色；只有用户明确要求原创改编时才另增原创候选行，并与源角色关联。字段至少有角色 ID、**角色卡图片（放在靠前可见的列；须以原视频角色帧垫图生成，通过第 2 节的原型、风格、三视图、动作与表情验收；不得用原帧、头像、陌生新角色或单纯站姿代替）**、**简介（描述卡中角色，写明画面可见的年龄段、性别若可辨、物种/类型、颜色、胖瘦与身形、毛发/服饰/配件、角色人设和情绪；不可判的属性不猜）**、类型/物种、角色人设（观察/推测）、原片风格、卡图风格、外形外貌/表情/动作/眼神四类画面证据及帧时间戳、整片流量快照及其限制、来源视频 URL、**视频原图（直接从当前原视频截取的一张代表帧，与角色卡分列）**、其他源帧 path、卡图垫图 path/时间戳、原型/风格一致性验收、复用状态、采集日期。差异化设计仅对用户要求的原创候选填写。旧记录缺证据时填“待逐帧复核”；旧卡与原型或风格不符，或缺三视图/动作/表情时填“待重制”，只有背景色不符的历史卡按上文例外保留。第三方源角色卡可作为带来源标注的分析资料入库，复用状态仍为“仅分析参考”；无合格卡时图片列留空并标“待重制”。网页报表应把合格角色卡图片同时写入 image 字段和行媒体预览，核对浏览器能直接看到，不以 API 返回图片 URL 代替页面验收。
- **`场景库表.md`**：每一行是一个场景，字段至少有场景 ID、**简介（描述、特点、气氛/情绪）**、原片风格、来源视频 URL、采集日期、**视频原图（直接截取的代表帧）**、原帧和时间戳、去角色前后对比图 path、AI 空场 path、地点/构图、可见角色布光、调色与后期建议、复用状态及局限。视频原图与 AI 空场必须分列并明确标注，不能把生成图冒充原帧。

总表直接链接到源帧、卡图、场景图和单视频采集记录。新视频只向这两张表追加/更新行；单视频记录使用 `采集记录.md` 或其他**非表库**名称承载长篇证据。相同角色的跨视频身份需要证据，不能仅凭外观相似合并。所有路径相对总表目录且应可解析；保留原片 URL 与数据采集日期。

## 5. 新视频选角选景与质量检查

从两张总表筛选风格、角色类型、动作能力、表演节奏、受众和制作约束相符的组合。源角色卡忠实记录原型，但第三方“仅分析参考”不自动取得制作复用权；只有权利已确认的源角色或用户明确要求的原创候选才进入创作资产筛选。解释源片观察与 AI 补全的边界。

打开最终卡图和空场，逐项验收：①能从记录追溯到作为 `image_gen` 垫图输入的原视频角色帧及时间戳；②源角色在三视图和所有面板保留可辨的脸、体形、毛色/肤色花纹、服饰道具及原片视觉风格，正、侧、背全身身份一致；③动作序列和表情眼神有原片画面依据，补全处明确标注，未跳舞的角色不被擅自改成舞者；④新生成/重制卡的所有空白区域及面板间隙抽样像素为 sRGB `#888888`，无场景/渐变/近似灰；⑤原创候选仅在用户明确要求时另行验收，不替代源角色卡。新卡任一项不合格就**不入库、不推荐、标“待重制”并重生成**。已入库旧卡须重新验收；若只有背景色不符而三视图、表情图和身份一致性均合格，按第 2 节历史卡例外保留并备注背景待统一；其余旧卡不合格则重制。场景另查透视和去角色痕迹。检查两张总表字段、链接、证据等级、复用状态和旧记录迁移。不得凭标题、缩略图或流量数字杜撰视觉细节。
