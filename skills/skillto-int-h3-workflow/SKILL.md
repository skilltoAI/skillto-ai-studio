# H3 原视频角色迁移 Workflow

这是 `skillto-int` 的子技能。输入是用户指定的 TikTok／抖音短视频 URL；输出是原片与证据化分析、角色和关键服饰道具的取舍、以及 SkillTo.ai 上本人可编辑的 H3 Workflow 草稿。直接使用完整原视频，不制作深度灰视频，也不因本站当前生成时长选项而自行截片。通用 MCP 操作、上传和运行遵循 `skillto-int-workflow-mcp`；每个定妆图片节点的提示词必须先读 `skillto-int-character-card` 及其直接引用合同，再按实际连线编写。建图前读 [H3 图合同](references/workflow-graph.md)，H3 提示词与角色取舍读 [角色映射与道具判断](references/analysis-and-prompt.md)。

## 1. 取得并核验原片

先读 `skillto-int` 和来源平台采集子技能。TikTok 用 `skillto-int-tiktok-crawler` 核实视频 ID、作者、时长和页面；实际媒体可由已安装的 `scrapling`／`scrapling-stream` 下载。直链失败而已核实的播放器可正常播放时，可用安装了 Playwright 的 Python 运行 `scripts/capture_tiktok_player.py <crawler-report.json> <source.mp4>`，借助采集子技能的已授权会话从普通 Edge 播放器媒体响应保存单条 MP4；脚本拒绝未核实或多条报告，不读取本地浏览器 Cookie 文件到工作区。抖音按 `skillto-int-douyin-xhs-crawler` 的授权会话规则办理。只处理用户获准访问的内容，不绕过登录、验证码、私密状态或 DRM。

每条视频独立保存 `source.mp4`、原 URL、视频 ID、作者、采集时间和下载方式。用 `ffprobe` 核对可解码视频轨、时长、宽高、帧率和音轨；页面封面、标题或元数据不能代替视频画面。无法取得原片时报告已证实的阻碍，不编造逐秒分析或可运行草稿。Cookie、Key 和时效媒体地址不得写入工作区报告。

## 2. AI Host 分析角色、镜头与取舍

完整观看原片，使用半秒或更密的时间戳原帧覆盖全片；候选硬切须回看相邻帧。复用 `skillto-int-depth-gray-replica` 的逐秒字段，写 `原视频视频分镜细节.md`：稳定角色 ID、位置／遮挡／动作、镜头和场景、可见事实与推测分开。AI Host 按可辨识度、出场时长和叙事作用选 1–3 个替换目标；超过三个时记录未替换者，难以可靠区分时让用户核对。听原片音轨并核对画面，逐个判断待替换角色是否有与歌声或人声同步的可见口型；记录证据时间段，只有明确需要时才要求新角色对口型。

逐件审查显著服饰和道具，按 [取舍字段](references/analysis-and-prompt.md)记录时间戳证据、动作／故事作用、保留／去掉／转译及与新角色形态的适配。可能改善开场识别、动作转折、笑点或结尾回应只是创作假设；整片播放量不能证明单件物品提高完播或互动。不得把第三方商标、角色身份细节或无关装饰自动搬到新角色。

同时核对道具和环境在片中是否发生**显著变化**，例如关键道具的出现、点亮、变色、转手或消失，以及场景切换、主照明或天气的明显改变。只有相邻原帧能证实变化且它影响动作、角色定位或视觉叙事时，才记录准确时间段、变化前后状态和证据帧，并写入 H3 提示词；普通运动、短暂遮挡或轻微亮度波动不算。没有明显变化时不添加“道具／环境变化”句，不为凑结构虚构事件。

## 3. 接收任意新角色照片并建图

函数输入是运行者提供的普通图片，内容在建图时完全未知：可以是动物、真人、卡通形象或物品，不能要求预制角色卡。需要演示默认图时，可从 `skillto-int-ip-store` 选取获准复用的本人素材，但卡 ID、名称和形态仅写在本地索引或输入默认值，不写进通用节点提示词。缺图时保留待补输入，不以原片人物、源卡或任意占位图冒充新角色。

用 `skillto-int-workflow-mcp` 发现工具和当前模型目录，克隆本人可编辑的 H3 草稿；不要修改源草稿。上传完整原片、需要的关键帧和可选默认输入图，使用服务端返回的本人素材 UUID。每个待替换角色各有一个函数图片输入端口和一个「新角色定妆后的角色卡」图片生成节点；输入照片先进入定妆节点，定妆节点输出才进入 H3。根据原片证据决定服饰和道具是否必须保留；需要视觉依据时，把同一原片的清晰关键帧作为定妆节点第二张参考图。调用 `skillto-int-character-card` 为每个定妆节点分别编写提示词：直说生成【新角色X＋输入照片引用】、移植【原视频待替换角色X＋关键帧引用】的哪些服饰道具、最终只能出现哪一个新角色且不得出现原角色。保持输入照片的原有视觉风格，并按原片动作适度拟人化；不要把照片或卡通形象一律写实化，也不要把物品强行变成人。

一个工作流只保留一个 H3 视频生成节点和一个视频函数输出。H3 的 1–3 张图片全部来自对应定妆节点，绝不直接连函数输入照片；图片顺序与原角色映射一一对应。H3 提示词从保存的实际连线生成引用，声音要求只写“所生成的视频必须严格采用原视频<原视频引用>的音频”。AI Host 事先确认某个待替换角色确有同步口型时，再为该角色加一句“所生成的视频中的【新角色X<定妆图X引用>】必须对口型”；否则不写口型要求。新角色只用定妆节点的引用表达，不写示例卡 ID、名称、预设物种或外貌。**H3 提示词最后一句必须明确列出允许出现的全部新角色及各自定妆图直接引用，并逐一排除原视频中对应的待替换角色；不能只写笼统的“不留下原角色”。**若原片有必须保留的未替换角色，另在允许名单中明确列出，避免误删。保存回读时检查该句仍位于提示词末尾、引用编号与实际连线一致、没有遗漏目标角色。模型、比例、时长、端口和提示词限制从 `workflow_list_models` 与 `workflow_get_node_options` 读取，不硬编码供应商内部字段。具体图和提示词规则见两份参考文件。

每次写入带最新 `draftRevision`，冲突时回读并核对，不覆盖网页编辑。保存后回读素材 UUID、输入默认值、两级连线和排序、定妆与 H3 提示词、比例与修订号；运行 `workflow_validate_draft`，在 `/drawing-workflow?wid=<uuid>` 验证同一草稿可见。编辑和上传是业务操作；本地路径和凭据不进入服务端草稿。

## 4. 时长、运行和交付

原片不自动裁成 15 秒。本站当前 H3 的 `duration_seconds` 选项为 1–15 秒，这是生成参数合同，不是输入原片上限。读取当前服务端选项并比较原片时长；超出现有可验证的完整输出能力时，保留原片和草稿，标记“待长时长能力核验”，收费提交前停止。只依据同一个 RunningHub 应用的节点合同和实际成片证据扩展时长，不能从其他 H3 产品或无上限的界面推断。整秒输出与原片有时长差时明确报告，不宣称逐帧等长。

建图不自动收费。用户授权本次真实运行后，先调用 `workflow_prepare_run` 检查输入、图片与视频两类模型报价、Key 许可和预算，再用稳定 `request_uuid` 调用 `workflow_start_run`；网络重试保持同一参数和 UUID，用 `workflow_get_run`／`workflow_list_runs` 找回终态。若服务端旧版本尚不能解析函数输入的网页默认媒体 URL，运行调用须显式传入该默认素材的 `material:<uuid>`；不要因此修改草稿默认值或发起第二次生成。结果只取服务端确认的最终视频；供应商中间阶段不算多次生成。实际预扣、结算和最终结果筛选由 SaaS 服务端负责。H3 当前没有独立音频输入：提示词要求采用原片音频；生成后核验实际音轨，并只对事先判定需要对口型的角色核验口型。提示词本身不保证模型原样复制音轨。

交付每条视频的 `source.mp4`、分镜细节、角色与服饰道具取舍、定妆与 H3 提示词、`workflow-index.json`、草稿 UUID／网页链接和校验状态。索引保存相对路径、SHA-256、来源时间、原角色映射、可选默认图片、关键帧及素材 UUID、工作流 UUID 和修订号；不得保存密钥或签名 URL。未实际运行时不声称已有定妆图或成片；生成后逐项核对身份、道具、动作、镜头、音轨和时长。
