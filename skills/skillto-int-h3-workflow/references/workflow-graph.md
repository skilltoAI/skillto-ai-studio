# H3 Workflow 图合同

以当前服务端 `workflow_list_models` 与 `workflow_get_node_options` 为准；中文节点名不是持久化类型。H3 FMS 首选稳定键 `rw-h3-character-transfer-video-v1`，图片模型须实时核对有可用路由、可接收所需参考图，并支持所选规格。模型运行许可与草稿可编辑性分别检查。

```text
函数输入：新角色1普通照片 ──→ 定妆图片生成1 ──┐
函数输入：新角色2普通照片 ──→ 定妆图片生成2 ──┤  按实际角色数保留 1–3 路
函数输入：新角色3普通照片 ──→ 定妆图片生成3 ──┤
原片关键帧资源（按需） ───→ 对应定妆图片生成 ─┤→ 唯一 H3 视频生成 → 函数输出：最终视频
完整原视频资源 ────────────────────────────┘
```

用户输入照片的形态完全不可预知。每个函数图片变量只连自己的定妆节点；关键帧是定妆节点可选的第二张参考图，用于原片服饰、道具和风格，不可成为身份来源。定妆节点输出与视频资源直接连 H3。禁止函数输入照片直接连 H3，也禁止把原角色关键帧、原片封面或默认卡直接连 H3。没有默认图片时草稿仍可保存，预检须报告缺失；可选默认图只用于演示，运行者可覆盖。

定妆图片排序键用稳定 `函数输入节点UUID:端口ID`，其次为关键帧节点 UUID；提示词相应使用 `{{image_1}}` 指新角色照片、如连接关键帧则用 `{{image_2}}`。H3 混合媒体排序按定妆节点 1–3、原视频资源节点保存，提示词分别用 `{{mixed_1}}` 至 `{{mixed_N}}` 指定妆图，`{{mixed_{N+1}}}` 指原视频。实际编号须从回读的连线与排序核验，不能仅根据节点位置猜测；服务端会把媒体引用转换成渠道令牌。H3 接收恰好 1 视频、1–7 图；本技能只用 1–3 张定妆图。一个 H3 任务只请求一个最终视频，供应商内部阶段文件不作为函数输出。

复制本人可编辑草稿后，为本次内容重建必要节点和连线，保留一个函数输入、1–3 个定妆图片生成、一个原视频资源、按需一个或多个关键帧资源、一个 H3 生成、一个函数输出。全部新关联使用稳定 UUID；函数输入默认素材只绑定本人可访问的 `materialUuid`。原视频画幅由本地解码宽高决定，定妆图的画幅独立。

本站目前的生成时长参数为整数 1–15 秒；输入视频 Schema 未设置 15 秒上限。完整原片超过当前可核验输出范围时，不改写原片、静默截片、重复节点或分段生成。草稿可保留，标记待能力核验并阻断收费运行。长时长验证后，服务端 FMS／BMS／Adapter 和网页选项必须同步更新；新上限由同一 RunningHub 应用的证据确定。H3 提示词对音频只写“所生成的视频必须严格采用原视频<原视频引用>的音频”；AI Host 核实待替换角色确有同步口型时才为该角色补一句对口型要求。H3 没有独立音频输入，须以真实成片核验音轨，不能把提示词当作音轨复制保证。

`workflow_validate_draft` 验证图合同；`workflow_prepare_run` 再确认整个依赖闭包的真实输入、图片与视频模型权限、预算和报价。用户没有授权真实收费运行时不得调用 `workflow_start_run`。一个 H3 任务的供应商内部多个 MP4 只能由服务端交付最终节点 `364` 的单条成片。
