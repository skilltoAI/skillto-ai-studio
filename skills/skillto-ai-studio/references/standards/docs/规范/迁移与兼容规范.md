# 迁移与兼容规范

适用触发：迁移、平移、备份、切换、回退。路径提示：`apps/stass/**/migration*`。多个命中必须累加读取。

状态：STASS 迁移目标约束，不代表对应功能已经实现或验收。

- 以实际启动配置、已安装技能、仓库代码和真实数据建立基线，逐项比较差异。先建立“原功能→原代码/数据→新模块→验收用例”矩阵，不能覆盖安装副本的有效功能。

- 清单覆盖数据库、JSON、媒体、Motion 原包/实例/输出、拉片导出、语音分段、历史、备份及数据根目录外被引用素材；记录大小、SHA-256、引用关系、目标和状态。

- 先检查空间和缺失引用，再在副本演练。正式切换前停写，等待已有任务完成；数据库采用一致性备份，SQLite 不能遗漏 WAL。保留原数据，复制到独立运行目录，不重编码已有媒体。

- 转换活动资源引用并保留历史原文。全量核对对象关系和文件哈希，新缺失、损坏及未解释差异阻止切换。旧有缺失明确报告，不能伪造资源。

- 迁移可重入、可断点恢复。一次性切换新 URL、启动器、扩展和 MCP 配置；禁止新旧服务双写。回退前保全新服务产生的数据，不得直接丢弃新增修改。

- 浏览器档案仅同机器同系统用户离线迁移。视图偏好使用白名单导出导入，不读取无关网站存储。PostgreSQL/Metabase 做一致性备份和隔离恢复。

- 停写后用明确指定的独立快照安装；拒绝接管原业务目录。迁入旧素材时按允许的来源和类型逐个复制核验，记录未找到项，网页响应转换访问地址，源记录保持可追溯。
