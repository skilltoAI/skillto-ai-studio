# 技术规范

每次开发、修复、重构和验证前必须读取本索引及版本与协作规范。按用户唤醒词、修改路径和实际影响累加加载下表规范；任务扩大时补读；不能归类时先读架构规范。

本文件是全项目权威索引。专项规范规定目标行为，现有已安装工作台是功能/数据平移基线。不能把目标规范、接口骨架或空页面称为已交付。

## 强制边界

- Windows x64 首发的完整安装从根 README 出发。用户向 Codex 或 Claude Code 发送一条安装请求，即可用官方发行包安装工作台与对应 Skills，并自动打开已验证的实例。宿主拦截自动执行时，给出可双击的绝对路径。macOS 首期提供已验收的 Skills 路径，工作台单独验收后再开放。各平台的实际支持范围和阻塞项须见 README。详见[启动器与部署规范](docs/规范/启动器与部署规范.md)。
- skills 是技能分发源；apps/stass 是独立程序源码归属。保留原功能、数据、媒体与各技能授权边界。
- GitHub 推送目标为 [skilltoAI/skillto-ai-studio](https://github.com/skilltoAI/skillto-ai-studio)。Windows 使用 Git Credential Manager 复用本机 GitHub HTTPS 登录，Codeup 继续使用独立凭据。公开推送前审查目标分支可达的源码和历史，获授权后回读远端提交。详见版本与协作规范。
- Git 拉取只更新开发源码。运行身份由不可变发行清单确定，程序、网页和匹配的 Skills 必须可追溯到构建提交。正式版本经统一管理锁、generation 比较和数据 schema 检查切换。详见[版本与数据一致性规范](docs/规范/版本与数据一致性规范.md)。
- 公开包只携带允许再分发的文件。个人链接及标题、凭据、浏览器档案和业务数据仅存入经用户配置的实例。发布前检查公开源码、可达历史和最终资产，首次安装使用空白实例。详见[文档模块规范](docs/规范/文档模块规范.md)和[测试与验收规范](docs/规范/测试与验收规范.md)。
- 本项目是个人项目。开发、修复或验证涉及本机 STASS 服务或引导程序重启、重新安装时，执行者应在本次任务内及时执行并验证，无需另行请求用户授权。本机操作沿用启动器与部署规范及版本与数据一致性规范。Git 推送、合并主分支、打标签和对外发布仍需明确授权。
- 同一 Windows 用户下 Codex、Claude Code、OpenClaw 必须共用一个 STASS 实例和数据根；宿主只部署技能与连接适配。统一安装、启动与升级锁，禁止各宿主复制业务数据或分别更新运行目录。详见启动器与部署、MCP与API规范。
- 子技能仅经 MCP 操作工作台。自身说明、静态资源、用户输入和临时文件不在禁令内。
- 默认8080，所有服务 URL 带 /STASS/；短链不等于授权。失败不换工作台、不降级本地文件。
- 逐模块实现、真实数据副本演练和验收完成前不得停旧服务或宣称迁移完成。

## 跨机安装故障依据

2026-11-21 的跨机案例用于约束后续实现和验收，以下情况均需回归验证。

| 现象 | 根因或证据 | 责任边界 |
| --- | --- | --- |
| 先装 Skills，再反复寻找和安装 EXE | 首轮仅复制技能。随后默认目录遇到文件移动错误，改装到 D 盘，宿主拦截创建和打开快捷方式。直接双击版本目录 EXE 时仍查找默认根的配置。文件移动失败的具体原因待日志确认。 | 统一安装器、稳定启动入口及分阶段结果。 |
| 新装后直接打开报表出现文件缺失 | 报表直接读取表格的 `catalog.json`。首次启动仅建立数据目录时，这个文件可能尚未生成。 | 统一数据初始化与空实例验收。 |
| 文件刚复制，仍显示旧「Motion 模版」顶栏 | 目标机运行路径显示 0.4.6。核查时，公开提交 `f54a7c1` 仍定义旧顶栏，本机 0.4.33 对应 `660528d` 并显示「AI资产」。目标机的清单摘要前缀与已查到的同版本留档不同，具体产物待完整清单确认。 | 以运行版本、完整提交和清单摘要诊断。文件时间戳仅用于排查复制过程。 |
| 他人新装后看到维护者个人飞书空间 | 程序和表格 Skill 的前端资源均硬编码个人链接，核查时公开源码和 0.4.8 离线候选包均包含引用。链接分发已确认，文档访问范围需在飞书单独核查。 | 个人配置隔离，审查源码和最终包，处置已外发产物。 |
