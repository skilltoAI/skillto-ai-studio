# Skillto.ai Studio 技术规范

版本：1.2 · 2026-11-15。适用范围：`skillto-int-table` 提供的本地工作台、集成页面及后续内容和功能开发。产品英文名为 **Skillto.ai Studio**，中文名为 **Skillto.ai 工作台**。

## Motion 模版扩展（1.2）

- 详情上一条/下一条位于视频左右两侧；控件采用无底色、无边框块与无阴影的半透明描边图标，悬停/聚焦增强，键盘聚焦保留细轮廓；序号和倍速文字同样弱化。右箭头下方提供 1X / 1.2X / 1.5X / 2X / 3X 预览倍速。本机浏览器 localStorage 键 `skillto.motion.previewRate.v1` 保存用户预览习惯，跨模板/重开/刷新生效，同源标签页同步；不写模板参数、不改变导出帧率或成片。详情和卡片悬停预览统一使用该倍速，非法或缺失值回退 1X。

- 桌面详情使用最多 1160px 宽的两栏浮窗：左侧完整视频与半星评分，右侧说明、维度、路径和操作；高度限定视口内，外壳与背景不滚动，超长信息仅右栏滚动。制作历史默认折叠。详情提供 Path/URL 图标及与卡片多选同步的选中按钮；无本机包时 Path 禁用。窄屏退为单列并允许内容滚动。

- 详情视频下方五星评分支持半星、悬停预览与清除，保存 0.5–5 / null；左右按钮和方向键按打开时筛选排序的列表切换，边界禁用，切换/关闭释放旧视频。详情自动静音播放，可通过播放器开启声音；浏览器拒绝时显示操作提示。

- 模板录入统一遵循兄弟技能 `skillto-int-motion/references/intake.md` 与 `assets/intake.schema.json`：先预检、整批校验、事务写入 `/api/motions/catalog`，再页面展示验收；建索引不能代替录入。`sync_index` 和 `ingest` 使用相同录入逻辑，稳定来源/画幅身份去重，保留人工编辑与已有工程。

- 源目录检索独立存储为 `motions/catalog-index.sqlite3`：画幅独立 ID、来源提交/文本哈希、FTS5、受控维度标签及证据、本地向量；词表和检索规则见 Motion 子技能 `references/indexing.md`。源目录与个人收藏分离，不能将预览条目或语义命中视为可下载/可执行。

- 兄弟子技能 `skillto-int-motion` 拥有独立服务、页面和运行适配；`MotionMixin` 接入现有 8880 Handler。顶部 `section=motions` 与公共导航事件保持一致，不增加第二个生产服务。
- `/api/motions/catalog`、`/api/motions/action`、`/api/motions/upload` 提供同一语义数据入口；AI 使用该子技能 CLI。SQLite、包、实例、媒体缓存位于 `SKILLTO_TABLE_ROOT/motions/`。内容与标签新增均走数据接口，不写模板专属页面。
- 左侧导航、右侧搜索筛选、等高卡片；预览容器 4:3、媒体 `object-fit:contain`；以静态封面副本 cover + 22px 模糊、低饱和压暗铺底，前景始终完整居中；无封面或加载失败使用中性灰底，不额外启动背景视频解码。画幅兼容是展示能力，不代表模板渲染支持任意画幅。
- 来源运行次数与个人 0.5–5 分（半星步进）独立，缺失值为 null；排序先运行次数再发布时间倒序、空值末尾、ID 稳定兜底。来源日期与收藏日期分别保留。
- 模块标签独立 CRUD；稳定 ID、改名保留关联、删除关联保留历史。卡片多标签完整保存，筛选支持全部/任一、无标签；不同维度 AND。
- 复制只显示图标，复制叠页为主体，右下中等大小文件夹/链环角标区分 Path/URL，带 tooltip 与 aria-label。Path 优先，指原始 .motion 本机绝对路径；不存在则空且禁用，不用 URL 代替。多选按当前列表顺序每项一行，缺失项跳过并报告。
- 原包检查不执行；首期仅已校验的公开中文版 Kinetic Tech 0.2.7-open-beta 可制作。未知引擎/版本和个人/保护封装明确标识。模板指南只作为资料，不自动注册技能。
- 每次制作独立实例，后台有界队列、取消终止所属进程树、失败保留日志和旧输出、重试新建任务。本地制作不得写入来源运行次数。原包、依赖、本机配置及成片不进入 Git。
- 模板网络媒体只经登记来源与受限同源入口，不能将原包 HTML/脚本作为 Studio 同源页面执行。已有模块 CSP 与接口保持不变。

本规范是开发入口。新增内容、字段、页面、组件、样式和接口前必须阅读；变更架构或交互约定时，同一变更中维护本文件及对应子技能。现有授权、数据和服务边界继续有效。本文标注“现状”的内容来自当前代码；标注“约定”的内容是后续实现必须遵守的规则，不代表已经交付。

## 1. 状态与兼容性

- 本地 UI 已按用户选定的 Codex 极简稿实施：顶部模块导航、14px 单行文档标题、常规字重目录、近白侧栏。公共样式 `assets/studio-theme.css` 最后加载，`assets/studio-shell.js` 只适配文档外壳；功能与数据仍由原模块拥有。安装副本仅同步本次资源。
- 改名覆盖产品显示名称、标题、导航品牌、启动器可见文案和帮助文案。机器标识 `skillto-int-table`、目录、MCP 工具名、环境变量、URL、稳定 ID 以及旧 EXE 文件名保留，兼容现有调用。
- 完整运行界面与启动器品牌替换随选定方案实施、验证；候选阶段不把预览宣称为已部署界面。
- 本规范不把远程 AMD-PAD 前端视为本地静态资源的副本。远程前端实施需要独立的适配和部署验收。

## 2. 已有架构和责任边界

```text
Windows Go 启动器
  └─ scripts/launcher_service.py（配置、回环 HTTP、浏览器用户、健康检查）
      └─ 配置指定的 HTTP Handler；本仓库为 reporting/serve_local.py
          ├─ 外部 douyin_tracker.review_web（表格基础 HTML/JS/CSS 和 HTTP 处理）
          ├─ assets/schema-controls.*（公共字段筛选、显示字段、媒体交互适配）
          ├─ assets/workspace-nav.*（模块导航、URL、模块切换事件）
          ├─ assets/report-system.* → scripts/report_system.py → Metabase / PostgreSQL
          ├─ assets/rewrite-system.* → scripts/rewrite_system.py + rewrite_voice*.py
          └─ 兄弟 skillto-int-workbench 的 WorkbenchMixin → SQLite / 媒体目录

AI 客户端 → scripts/server.py 的 stdio MCP
          ├─ 本地：catalog.json + tables/<稳定 ID>.json
          └─ 已配置远程：remote_client.py → 认证 HTTP MCP → AMD-PAD 共享存储
浏览器用户 AI 操作 → browser_mcp.py → 本地启动器服务 → browser_profiles.py
```

| 模块 | 实现 / 接口 | 权威数据与限制 |
| --- | --- | --- |
| 表格 | `scripts/server.py`，基础 review 页面及 `schema-controls.*` | `SKILLTO_TABLE_ROOT/catalog.json`、`tables/<id>.json`；知识库 > 项目 > 表格 |
| 公共导航 | `assets/workspace-nav.js`、`.css` | 当前 URL 的 `section`；表格、报表、拉片、洗稿、文档、排稿、工具；附浏览器用户入口 |
| 报表 | `report-system.*`、`report_system.py`；`/api/reports`、`/api/reports/catalog`、`/api/reports/item`、`/api/reports/embed`、`/api/reports/lineage`、`/api/reports/refresh` | `reports/catalog.json`、派生查询库；Metabase 为独立服务。通过 `skillto-int-reports` 操作 |
| 洗稿 | `rewrite-system.*`、`rewrite_system.py`；`/api/rewrites` | `rewrites.json`；V0 原文不可变、版本稿件、每版 Prompt、八项分析、人评、素材及跨平台引用 |
| 配音 | `rewrite_voice.py`、`rewrite_voice_worker.py`；`/api/rewrites/voice`、`/api/rewrites/voice-status` | 固定小与语音配置，生成产物属于运行数据；遵守 `skillto-int-rewrite` 的生成边界 |
| 拉片 | 兄弟 `skillto-int-workbench`；`/breakdowns`、`/api/workbench/*` | `SKILLTO_TABLE_ROOT/workbench/` 下独立 SQLite 和媒体；独立 REST，不伪装成表格 MCP |
| 文档 | 公共导航中的飞书链接 | 现状是打开外部文档，不是本地文档 CRUD 系统 |
| 排稿 / 工具 | 公共导航中的预留页面 | 现状尚未接入；必须如实显示，不能在新皮肤中伪造可用功能 |
| 浏览器用户 | `assets/browser-users.*`、`browser_profiles.py`；`/browser-users`、`/api/browser` | 独立持久化 Chrome 档案和 Cookie，仅本地，不迁移 AMD-PAD |
| 启动器 | `scripts/windows/*.go`、`launcher_service.py` | `launcher.local.json`、回环 8880、健康检查、启动/关闭/复用；构建 EXE 为本机产物 |
| AMD-PAD | `remote_client.py`，远程 `/api/report-tables/mcp` | 认证、共享 `data/report_tables/`；显示入口 `/report-tables?table=<id>` |

插件同步使用同一个本机服务与自动同源配对，视频经认证的有界连续数据块直接传入任务生成的内部目录，不能依赖 Chrome 下载路径或要求用户配置第二端口。所选片段处理完成后，再自动打开对应拉片记录；已有工作台标签页时复用并聚焦。完整浏览器下载和独立片段导出不能新增拉片记录。

当前集成风险：`reporting/serve_local.py` 仍依赖外部 `douyin_tracker.review_web`，并含安装目录回退及维护者研究资源适配。不能声称仅安装本技能就包含完整基础前端。新模块一律从加载的技能目录解析资源和兄弟能力；禁止增加新的硬编码安装路径。此次视觉升级不顺带重构既有服务或迁移存储。

## 3. 新内容优先使用数据和配置

| 请求 | 应采用的扩展方式 | 何时才需要业务代码 |
| --- | --- | --- |
| 新知识库、项目、表格、行、标签 | 语义 MCP 的 workspace / define / save / tags / review 工具 | 现有操作无法表达且需要新行为时 |
| 新列、新筛选、显示隐藏列 | 声明 `fields` 的类型、名称、标签、选项；公共控件自动生成 | 新的字段类型，须补齐公共渲染、筛选和校验 |
| 新内容分类、行业、主题、素材 | 表格数据或表内标签 | 不允许为一个主题或表格 ID 写专用 UI |
| 新报表、图表 | 报表服务 CRUD，复用 Metabase 和报表树 | 新的报表能力或接口 |
| 新稿件、版本、分析内容 | 洗稿 REST，经对应子技能处理 | 新业务行为或版本结构 |
| 新拉片、视频、分镜笔记 | workbench REST | 新下载协议或分析能力，仍遵守该技能授权边界 |
| 新一级模块 | 先确认现有模块不能承载；沿用公共外壳、Token、导航与交互约定 | 需要新数据生命周期和业务能力时 |

目标是“增加常规内容无需改代码”，不是承诺任意新功能都无需开发。不得用直接编辑 JSON、浏览器本地存储、复制专属页面等方式绕过服务。

### 字段和数据不变量

1. 保持知识库 > 项目 > 表格的稳定 ID；重命名只改变名称。完整数据结构见 [schema](references/schema.md)。
2. 九种现有字段类型全部保留：text、number、date、boolean、image、video、single_choice、multiple_choice、short_video_info。未知导入列原样保留。
3. 筛选按类型生成；数字边界含端点、支持小数、空值不视为 0；日期范围有可见错误反馈。字段、搜索和标签按 AND 组合；显示结果和生效条件数。
4. 隐藏字段不影响数据、导出和筛选。列偏好按表格稳定 ID 隔离，只属于当前浏览器的视图偏好。
5. 标签定义属于单表；多选完整保存且不覆盖其他字段；空标签行也必须有“编辑标签”。评分与标签、图片人工选择相互独立。
6. 行/表历史仅追加；删除保留快照；导入导出保留历史。图片重新生成清除该图片旧选择。
7. 视频默认单元格小窗、悬停/聚焦中型播放、点击全屏、触屏可点击；离开、重绘、关闭时释放播放。媒体在公共组件实现。
8. 数据写入成功指已到达服务和磁盘；“保存中”“已保存到磁盘”“保存失败”“仅浏览器恢复副本”必须区分。

## 4. 统一视觉系统

### 固定方向

白色工作画布、近白导航、灰黑文字；绿色仅保留在主界面 Logo。采用 Codex 参考图的克制侧栏、低对比选中背景、细分隔线和清晰空间层级，并按用户要求将一级模块放在顶部导航；不复制其业务内容。平面工作区为主，不用大面积渐变、装饰性 KPI 卡片或彩色导航。

以用户红框 Codex 截图取色：画布 #FFFFFF、侧栏 #FDFDFD、次级背景 #F9F9F9、分隔线 #E7E7E7、选中 #ECEDED、正文 #3C3E40、辅助 #6C6D6F。按钮 #26282B、焦点 #525456。Logo 保留绿色箭头；真实媒体、用户标签及错误语义色保持其含义，不对媒体应用灰度滤镜。

### 基础 Token（选定布局前的公共基线）

新增样式必须引用语义 CSS 变量。最终交付时由一个共享 Token 文件提供，并由公共组件消费；不得让每个模块复制独立色板。以下名称是目标约定，当前旧页面尚未全面接入。

| Token | 基线 | 用途 |
| --- | --- | --- |
| `--studio-bg` | `#ffffff` | 主工作画布 |
| `--studio-sidebar` | `#fdfdfd` | 导航面 |
| `--studio-hover` | `#f9f9f9` | 悬停 |
| `--studio-selected` | `#eceded` | 选中背景，结合文字加深和 aria-current |
| `--studio-text` | `#3c3e40` | 正文、图标 |
| `--studio-muted` | `#6c6d6f` | 辅助信息 |
| `--studio-border` | `#e7e7e7` | 区域分隔 |
| `--studio-action` | `#26282b` | 绿色主按钮背景，白字 |
| `--studio-action-hover` | `#3c3e40` | 主按钮悬停 |
| `--studio-brand` | `#27b84a` | 主界面 Logo 品牌绿，不作为小字颜色 |
| `--studio-focus` | `#26282b` | 2px 焦点轮廓、2px 间距 |
| `--studio-danger` | `#b42318` | 破坏性操作和错误文本，配文字或图标 |
| `--studio-success` | `#26734d` | 真正的成功状态，配状态文本 |

- 字体：系统 sans-serif，中文回退 PingFang SC / Microsoft YaHei / Noto Sans CJK SC。最多两套字体；数字用 tabular-nums。不得要求在线字体才能阅读。
- 字号：11–12px 注释、13px 导航、14px 正文、14px / 500 单行文档标题（图标 + 标题，无面包屑、说明、数量徽标）；弹窗标题 16px。重要业务文字不使用极淡灰。
- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48；边框 1px；控件圆角 6–8px、弹窗 12px。阴影仅用于浮层，不给每个内容区加卡片。
- 图标：同一线性系统，16–20px、约 1.5px 描边、currentColor；图标按钮有可访问名称。
- 控件高：常规 32–36px；触屏交互区域至少 44px。表格紧凑但不牺牲媒体与标签编辑入口。
- 动画：120–180ms 的背景、透明度和轻微位移；侧栏/浮层最长 220ms；尊重 prefers-reduced-motion。禁止为纯装饰反复播放。

### 导航和页面外壳

保留全部模块和知识库 > 项目 > 内容三级关系。一级模块表格 / 报表 / 拉片 / 洗稿 / 文档 / 排稿 / 工具统一位于顶部头部；左侧用于知识库、项目和内容树，不再重复一级模块。候选可改变头部和侧栏的视觉密度，不更改层级或模块职责。URL、面包屑、侧栏选中项必须一致，前进后退和刷新可恢复选中内容。

统一外壳负责品牌、模块导航、树、面包屑、状态和页级动作；模块只提供内容区。新增模块不得另造一套导航。保留 `workspace-section-change` 事件和现有 `section` / `table` / `report` / `manuscript` URL 契约。

桌面 >=1280px 显示完整导航；768–1279px 可收起侧栏；<768px 使用有关闭按钮、遮罩和焦点管理的导航抽屉。宽表只在表格容器内横向滚动，不能撑宽整个页面。

### 组件和交互

- 每页最多一个强调的主动作；次要动作用线框/文字按钮，破坏性动作放确认弹窗，明确对象及非空父级的后代。
- 列表有加载、空、无搜索结果、失败、无权限状态；只有确实可操作的动作才显示可用按钮。
- 弹窗支持 Esc、焦点约束及关闭后焦点返回；菜单支持键盘操作；提示不只靠颜色、悬停或瞬间 toast。
- 表格编辑、筛选、评分、媒体、标签与历史沿用原行为；视觉方案不能以简化界面为由删掉能力。
- 主内容使用业务用语；MCP、JSON 路径、脚本、内部 ID 等只出现在诊断/高级区域。
- 正文对比度目标至少 4.5:1，控件边界和焦点至少 3:1；在桌面、触屏、键盘和 200% 缩放下验收。

## 5. Logo 和品牌资源规范

用户最新确定：Logo 指 UI 主界面的完整横向品牌标识。沿用提供的 skillto.ai 黑灰字形与绿色 t/o 上升箭头，加细灰分隔线，右侧原 STUDIO 改为「个人工作台」，以精致中文字重和间距强化时尚感。产品正式名称仍为 Skillto.ai Studio / Skillto.ai 工作台；Logo 副标为个人工作台。
选定后，生产资源放在技能 `assets/brand/`：主界面横向 Logo、中文辅助字标及所需的浅色底版本。源文件与导出尺寸明确记录；生成位图只是候选，不把它声称为矢量源文件。本轮不包含 EXE、任务栏、桌面、favicon 或其他程序图标设计。

- 主界面 Logo 展示完整文字与箭头；四周保留光学留白，不能切掉箭头尖端。
- UI 使用 `object-fit: contain` 和横向容器。严禁将整条横版 Logo 用 `cover` 塞进方形图标位。
- 顶部页眉使用 218px 品牌槽，图片 208×44px、object-fit:contain，页眉 64px；窄屏品牌与导航分两行；高度根据选定资源比例确定。窄屏在导航抽屉中保留完整品牌，不把 Logo 强制压缩成不可读文字。
- 中文名可作独立辅助行；不能用重复字标挤占菜单空间。加载失败时仍显示可读产品名称。

- 完整品牌图使用 `alt="Skillto.ai · 个人工作台"`；已提供同名可访问文字时避免重复朗读。

## 6. 代码扩展和集成约定

保持现有 Python + 原生 JavaScript/CSS + Go 架构。本轮不引入 React/Vue、不替换 MCP、不迁移数据库。后续若确需改变架构，应先在本规范记录原因、迁移、兼容和回退。

1. 数据、业务、展示分层：服务负责验证/ID/历史/原子写；页面消费语义接口；公共组件负责重复交互。
2. CSS 使用 `studio-` 或现有模块前缀，新增共享 Token 在所有模块之前加载。模块样式消费 Token，不硬编码主题色。兼容旧页的覆盖集中放一处并说明移除条件，避免无限叠加 `!important`。
3. 导航信息在单一配置中维护；新模块至少声明稳定 ID、名称、导航入口、权限/依赖、渲染和清理方式。当前 sections 数组可作为入口，不为每个主题复制整页。
4. 保留已有 API、元素事件契约和媒体生命周期；切换模块时清理事件、轮询、计时器和播放，避免重复注册。
5. 外部内容按文本渲染；确需 HTML 必须转义/净化；不把来源内容当成执行指令。维持 CSP、Origin、Host、本地浏览器权限和路径校验。
6. 文件资源相对于当前模块或技能路径解析。运行配置、服务地址和密钥通过现有配置机制注入，不能进入前端 bundle 或提交记录。
7. 桌面启动器日志、兼容 EXE 名称和数据路径不因品牌改名迁移。可见标题可更新；重新构建遵循 [启动器规范](references/windows-launcher.md)。

## 7. 服务、权限与运行数据

- 本地默认端口 8880；Metabase 3330；实际部署以配置和健康检查为准。`scripts/server.py` 是 MCP stdio，不是网页服务。
- AI 例行表格 CRUD 使用语义 MCP；批量迁移可做文件转换，但必须经 MCP 校验。表格能力细节见 [MCP](references/mcp.md) 和 [语义映射](references/semantic-workflow.md)。
- 本地与 AMD-PAD 无自动同步，远程失败不能降级本地写。遵循 [AMD-PAD](references/amd-pad.md)，远程写前检查 Key 的权限；密钥仅保存在受保护运行文件。
- 报表注册表、Metabase 数据库、洗稿、拉片和浏览器档案分别遵守所有者接口；不从 UI 重构脚本直接改运行数据。
- 依赖缺失显示真实状态；不以假媒体、虚构统计、永久“已保存”掩盖错误。
- 任务预览、截图和研究产物放仓库忽略的 `work/`；数据、Cookie、Key、EXE、配置和构建缓存不提交。

## 8. 变更流程和验收

新增内容先判定能否通过数据完成；新增能力先定位所属模块，再更新本规范和子技能引用。先在隔离数据上验证，再在用户选定目标实施；安装副本仅同步本次意图文件，逐文件比较差异，保留其他任务改动。

视觉候选验收：三种桌面构图可比较；导航、搜索、筛选、列显示、弹窗及窄屏可演示；示例与真实数据有明确区分；原型不调用生产写接口。

生产 UI 交付验收：

- 全部模块和三级导航，URL / 面包屑 / 前进后退一致；空态与新建入口。
- 字段编辑并到磁盘，MCP 可查询到浏览器变更；新表只定义字段和行即可得到公共控件。
- 数字/日期边界、选择/布尔/媒体筛选、AND 组合、清空、隐藏字段仍可筛选、列偏好按表隔离。
- 标签新建/改名/删除，行内新建标签，分配两个再移除一个且不影响其他数据；评分和理由。
- 图片/视频预览、全屏、键盘/触屏、播放资源释放；多候选选择/取消和替换后清除旧选择。
- 导出/导入历史、删除快照、保存失败提示；原服务权限及隔离保持。
- 报表、洗稿版本/Prompt/评分/配音、拉片、外链文档和浏览器用户按实际能力回归；未接入入口如实标注。
- Logo 所有目标尺寸、200% 缩放、键盘焦点、窄屏滚动范围；无控制台错误。

仓库检查遵循根目录 `CONTRIBUTING.md`：`python scripts/validate_repo.py`、`python -m unittest discover -s tests -v`、`git diff --check`；业务变更另运行对应已有测试。视觉候选阶段不得声称完成生产 CRUD/远程回归。发布和 Git push 需要用户明确要求。

### Motion 浏览状态与默认评分

右上角提供全部／已浏览／未浏览筛选，组合现有筛选并通过 URL 保留。打开详情（含上／下一条）经服务端 `view` 记录 `viewed` 和首次 `viewedAt`；悬停、同步、导入不视为浏览。历史无明确记录的条目为未浏览，不根据评分反推。已浏览且无人工分数时默认 1 分，`ratingSource=view-default`；人工半星评分优先，清除后恢复默认 1 分。与来源运行次数完全独立，持久化并保留修改历史。未浏览筛选下打开后从列表消失，详情上下条沿打开时列表快照导航。白名单预览原子缓存上限 512 MiB，支持缓存后 Range 播放，首次需下载完成；包下载及来源限制不变。

### Motion 示例媒体压缩策略

录入/同步后后台 mediaJob 检查 demo；大于 40,000,000 bytes 必须生成 H.265/hvc1 720p（横屏1280×720、竖屏720×1280）等比预览，禁止放大/裁切。校验时长、尺寸、编码和音轨后发布；临时大原版在成功、失败或取消时清理，仅长期保留派生视频。小视频不重编码，后台只检查大小，播放时才缓存。共享处理器也用于历史缓存和首次预览；.motion 原包与 URL 不变。dryRun 不访问媒体；元数据提交与媒体任务完成分别验收，mediaError 不代表数据回滚。

### Motion 人工评分区间检索

工具栏「评分」支持 0.5–5 分、半星步进、含上下限区间，可只填一端。评分来源可选全部／仅人工／仅默认／未评分；选择未评分时清空并禁用区间，空分数不匹配数值区间。历史无来源的数值分数视为人工评分。下限大于上限时阻止提交并提示，不改变已生效筛选。与搜索、标签、浏览状态等 AND 组合，通过 URL 持久化，显示当前条件。清除评分筛选只清除其自身；全局清空全部重置。查询不改评分、来源运行量和浏览状态。


## 双版本多行编辑

稿件版本区使用「双版本编辑」打开左右两个完整的多行文本框，各自下拉选择版本。两框字号、行高、顶部内边距和初始高度一致，保留原有换行、空行和标点，不自动分句、不生成逐句表格、不插入对齐占位行；按原有换行逐行显示并双向同步垂直滚动。两侧非V0版本均可编辑，自动保存到各自版本；同版本同时显示时正文同步。V0正文只读。单版本编辑仍保留全文、Prompt和逐行标注能力。

左右切换版本、切换编辑模式及新增版本前刷新两侧待保存正文；失败保留草稿并阻止切换。保存沿用现有 save_version、版本 Prompt、逐行标签、历史和语音失效规则。对比开关与左侧选择为本浏览器按稿件隔离的视图偏好，右侧编辑版本仍通过 select_version 保存。

验收使用隔离稿件：两个完整文本框、相同垂直行几何、同步滚动、两侧独立落盘、换行空行保留、Prompt/标签保留、V0只读、编辑后立即切换和刷新恢复。

## 稿件内分析 Tab

每篇稿件顶部的稿件卡片提供「稿件版本」「文稿分析」「关键帧分析」三个 Tab；切换前保存待写入的版本和分析，失败保留草稿并阻止切换。支持方向键、Home/End、窄屏表格横向滚动。当前 Tab 是按稿件隔离的浏览器视图偏好，可用 `rewriteTab` URL 参数直接定位。已有稿件读取时补齐空分析，新稿件直接提供相同入口，不需要为单篇定制页面。

分析属于稿件，不属于某个口播版本，不能进入配音或逐字稿。字段 `manuscriptAnalysis`、`keyframeAnalysis` 均为 `{"text":"","revision":0,"updatedAt":""}`，正文支持安全子集 Markdown（标题、段落、列表、表格、HTTP(S)及既有素材链接；不执行 HTML）。人工通过「编辑分析」「保存分析」修改；切换前也会保存，状态明确区分未保存、保存中、已保存到磁盘与失败。刷新前若有未保存修改会提示。

AI 通过 `POST /api/rewrites` 的 `save_analysis` 动作写入：`id` 为稿件ID，`analysisKey` 为上述二者之一，`text` 为正文（最多100000字符），`expectedRevision` 为刚读取的整数修订号。修订冲突拒绝覆盖，写入追加历史；一般 `update` 保留服务端现有分析，旧表单不得擦除它。保存分析不改变V0、改写版本、Prompt、行标签、配音或人评。

文稿分析按指标分别写原句/时间、写法、心智与情绪机制、局限；不得把可见互动数当作完播率或互动率的分母。关键帧分析先审看3×3拼图，再以表格记录画面事实、设计优点、可能机制、不足和改进；提供拼图格位与可靠时间，采样记录不一致时保留说明，不把静帧推测成已确认的连续动画。

验收覆盖隔离数据的旧稿补齐、两分析独立保存、刷新恢复、修订冲突、一般表单保护、历史、HTML注入转义、版本编辑切换落盘、保存失败保留、键盘与手机宽度。原八项分析与人工五心评分继续保留。

## 洗稿步骤与分镜审阅

稿件顶部使用六步图标导航：文案版本 → 原文亮点 → 原视效亮点 → 前12秒分镜 → 12分镜表 → motion分镜表。沿用 rewriteTab 的旧 script/manuscriptAnalysis/keyframeAnalysis 标识；新增 openingStoryboard/fullStoryboard。黑灰为主、当前步骤深石墨绿，连线浅灰；不引入旧版 Ant Design 运行依赖。原稿信息折叠进标题旁 ⓘ，支持悬浮、聚焦、点击及 Escape。

两种分镜均属于稿件，以 {rows,revision,updatedAt} 保存。每行 id/title/time/narration/description/animation/prompt/feedback/frames；frames 最多4项 {url,label}，只接受 HTTP(S) 或 /assets/ 素材地址。空 feedback 表示暂时不用修改，不自动写成“通过”。12秒是模块名称，已有约10秒设计不自动伸长。AI 用 POST /api/rewrites 的 save_storyboard，传 id/storyboardKey/rows/expectedRevision；保存冲突不得覆盖。旧稿自动补空，不进入逐字稿或配音。原有八项分析、人评和版本保留。修改、添加、删除分镜后显式保存或切换步骤前保存，失败留草稿；刷新未保存提示。通用编辑 UI 不绑定稿件ID。

## 前12秒分镜版本

显示名改为“前12秒分镜”，openingStoryboard URL/机器标识保持兼容。保留原 rows/revision/updatedAt 并增加 versions 与 activeVersionId；首次读取旧数据建立 V1 原方案，逐行人工意见与图均原样保留。每个版本独立保存 rows/revision/createdAt/updatedAt/id/label，顶层 rows 为当前版兼容视图，顶层 revision 用作全局并发保护。新增版本复制当前版（含意见），切换前先保存，失败保留草稿并阻止切换，支持重命名。上限30版，所有操作记录历史。POST /api/rewrites 新增 create_storyboard_version / select_storyboard_version / rename_storyboard_version，必传 id/expectedRevision；创建可传 label/baseVersionId，切换和改名传 versionId，改名还传 label。save_storyboard 可传 versionId，拒绝与当前版本不符；旧客户端的 expectedRevision 同样防止跨版本误覆盖。不改变文案版本、原亮点分析和完整分镜表。

美术约束：纯矿物白底、黑灰少量锈红；可独立拆分的3D白模图例、3D线稿和矢量信息图，不用大面积写实云海或全景。小幅IP图片可作为明确边界的独立图像层。PNG是审阅快照，SVG源文件的分组才是本次可拆解图层；不得把2.5D矢量图例宣称为已交付三维网格模型。


## motion分镜表与统一版本按钮

洗稿增加 `rewriteTab=motionStoryboard`，表示稿件全片分镜的表格版本；与前12秒分镜、既有12分镜表及口播版本独立。「前12秒分镜」和motion采用与文案一致的横向V1/V2按钮，保留原版本ID和自定义名，不伪造分镜V0。切换持久化、失败阻止切换；旧稿无损补空模块。

motionStoryboard只持有带修订号的表格版本引用；正文使用原通用表格组件，以同源 `rewriteEmbed=1` 内嵌并隐藏重复导航。只在选中步骤时载入，离开释放媒体；未完成编辑、正在保存或保存失败时阻止切换。原表关联为首版；新增版本在同项目复制整表到新ID，保留schema、未知字段、媒体、评分、标签和历史，独立编辑。复制和表格CRUD共享存储锁，登记失败回滚本次新表，不动原表。服务将当前表格store注入rewrite模块，不新增硬编码安装路径。

API为 `link_motion_storyboard` / `create_motion_storyboard_version` / `select_motion_storyboard_version` / `rename_motion_storyboard_version`，均携带id和expectedRevision；详细参数、人工评分与制作边界见 [洗稿技能](../skillto-int-rewrite/SKILL.md#分镜步骤与版本管理)。此关联不执行生成、渲染或发布。验收需验证版本隔离、刷新恢复、失败草稿保护和原表数据不变。
