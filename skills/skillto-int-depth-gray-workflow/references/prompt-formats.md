# 工作流节点 Prompt 格式规范

本文件供 `skillto-int-depth-gray-workflow` 建图时使用。先读 `skillto-int-workflow-mcp`，通过 `workflow_get_node_options` 获取当前节点真实引用规则、模型能力和参数枚举。下列 `<...>` 是编写时占位符，保存节点前必须替换成实际内容；`{{mixed_N}}`、`{{text_N}}` 是画布引用令牌，N 依当前节点的连线顺序确定，不能把字母 N 或 X 原样提交。节点输出来自上游实际结果，不以节点标题代替正文。

## A. 新角色 N 照片理解：文本节点

**输入**：函数输入的该角色照片；只连接同一个角色的照片。**输出**：一个 UTF-8 JSON 对象，无 Markdown 代码块、解释、前后缀或第二个对象。键固定为 `新角色名`、`新角色特征`，均为字符串；名称恰为六个汉字，特征不少于 80 个汉字。对年龄、人种、肤色等只写可见或可合理判断的外观，不确定或不适用时明确说不适用/不可判，不能把动物或物品写成人。照片与分析必须一一对应。

保存到每个角色理解节点的 prompt 模板：

```text
你只分析引用照片中的一个新角色。<角色照片引用> 是新角色<角色序号>。先判断它是人、动物、卡通形象还是物体；只依据可见画面描述，不继承待替换旧角色的外貌，也不推测看不见的身体部位。
给它一个恰好六个汉字的简短修饰性称呼，只给一个。用不少于80个汉字描述其可见外貌与辨识特征：适用时写外观年龄阶段、颜色、种类或人种、肤色、毛发、四肢/可动部位、体型、表情、纹理和配饰；不适用或不可判的项目不要编造。
只输出一行合法 JSON，使用双引号和以下两个键，不要代码块或其他文字：
{"新角色名":"<恰好六个汉字>","新角色特征":"<不少于80个汉字的可见特征描述>"}
```

`<角色照片引用>` 替换为该节点实际图片引用，例如 `{{mixed_1}}`；`<角色序号>` 替换为 `1` 或 `2`。输出需通过 JSON 解析、恰好两键、六汉字名称和 80 汉字特征检查；失败时停止下游，不把错误文本当成角色资料。

## B. 新角色 N 角色卡：图片生成节点

**输入**：同一角色的原照片和 A 的完整 JSON 正文。**输出**：一张角色卡图片。用户指定 GPT-Image 2.5、2k、26:9；具体 FMS UUID 和参数原值先查模型目录与节点选项。模型、2k 或 26:9 不支持时，不静默换型号、分辨率或比例。角色卡是预期生成物，创建草稿时不能把原照片写成已生成角色卡。

```text
以 <原角色照片引用> 作为唯一角色身份依据，以 <角色理解文本引用> 的 JSON 为外貌核对说明。生成同一角色的 26:9 宽幅、2k 角色卡，统一深灰色简洁背景、柔和一致照明。画面按从左到右排列清晰的正视、侧视、背视三视图，并在不遮挡三视图的位置加入该角色可表现的表情细节图；同一角色在所有视图中保持物种/形态、毛色或肤色、脸部特征、体型、配饰一致。若输入是没有脸或表情的物体，把表情图区改成关键结构与纹理细节图。保留原照片可见的身份特征，不复制原视频待替换角色的外貌、服饰或物种。不要额外角色、场景、文字、标签、水印、拼错的肢体或被裁掉的关键部位。
```

`<原角色照片引用>` 替换为此节点实际图片令牌（常见 `{{image_N}}`）；`<角色理解文本引用>` 替换为实际 `{{text_N}}`。两条来源必须是同一个角色，且模型确实接收这张输入图；报价和实际请求应包含两者。图片节点参数分别设为服务端返回的 2k 与 26:9 枚举值，不能仅在 prompt 中写规格。产物检查三视图、身份一致、深灰背景和实际画幅。

## C. 全能参考视频 Prompt：文本节点

**输入**：每个在场新角色的 A 节点 JSON 正文，以及 `原视频视频分镜细节.md` 的完整正文。仅有一个新角色时删去第二角色引用及相关要求。**输出**：供视频生成节点直接消费的纯文本 prompt，必须保留原视频的时段、硬切、机位与动作顺序。生成节点不能仅连接分镜文件名或角色节点标题。

```text
你要为“以深度灰视频为动作与时序控制、用新角色和新场景替换旧画面”的视频生成节点编写最终提示词。
新角色1资料：<新角色1文本引用>
<如果有第二角色：新角色2资料：<新角色2文本引用>>
原视频分镜与逐秒证据：<分镜细节文本引用>

只依据上述输入写最终提示词，不增加看不见的剧情、外貌或镜头。先从分镜中建立【待替换角色N】到【新角色N】的一一映射：用旧角色的位置、深浅层次、轮廓、动作、遮挡来定位替换对象；用新角色资料定义新身份。保留旧角色在各时段的服饰/道具功能、姿态、眼神和情绪节奏，但不要把旧角色的物种、肤色或外貌覆盖到新角色。把背景替换为用户提供的场景图，只保留动作所需的空间关系。深度灰视频控制时长、帧序、景别、机位、运镜、硬切与动作；角色卡控制新角色外貌。原音频只有在视频模型实际支持并接入音频输入时才写“同步原音轨”，否则写“音频另行交付，成片音轨未保证”。

输出严格使用以下标题和顺序，不写分析过程或 Markdown 代码块：
【目标与输入职责】一段，分别说明深度灰视频、角色卡和场景图的作用。
【角色替换映射】每个新角色一行，写“待替换角色ID → 新角色名；定位线索；保留的动作/服饰/道具功能”。
【场景替换】写新场景图怎样替换背景，以及必须保留的空间功能；不编造图中不存在的细节。
【分镜与逐秒时间线】按原视频从0.00秒到片尾逐段连续列出“起止时间｜scene/硬切｜机位/景别/运镜｜各新角色位置、动作、表情、眼神｜场景空间功能”；末段按真实片尾结束。
【一致性约束】写角色身份、动作顺序、遮挡、硬切、时长不得漂移；出现不可判内容时保持不确定。
【音频】只按实际音频连接状态说明同步目标或音频另行交付。
```

将三个 `<...引用>` 换成此节点真实的 `{{text_N}}` 编号，保留来源身份及顺序。最终输出检查标题齐全、角色数与输入一致、时间线无缺秒/重叠、硬切位置与分镜一致、没有凭空补充的情节；再检查展开后的字符数满足所选视频模型合同。若模型合同装不下完整时间线，先调整可用输入方式或模型，不默默丢秒。

## D. 视频生成节点的直接 Prompt

视频节点必须实际连接深度灰视频、每个角色卡、场景图和 C 的文本输出。它的编辑器提示词只需明确引用 C 的实际 `{{text_N}}`，并说明连接媒体的职责；不要把同一份长分镜正文又手工粘贴一遍：

```text
按 <全能参考prompt文本引用> 生成视频。连接的深度灰视频负责原片时序、机位与动作；连接的角色卡负责新角色外貌；连接的场景图负责新背景。保持提示词中的角色映射、逐秒时间线与硬切。不要新增人物、镜头或剧情。
```

保存前将 `<全能参考prompt文本引用>` 换成真实 `{{text_N}}`；检查所选视频 FMS 真正支持这些视频/图片/文本输入数量及格式。若音频没有受支持的连线，不宣称输出含原音轨。完成输出必须由运行终态和素材 UUID 证明。
