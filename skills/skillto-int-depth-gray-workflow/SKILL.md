# 深度灰视频复刻：本地素材到 SaaS Workflow

这是 `skillto-int` 的子技能。复制并延伸 `skillto-int-depth-gray-replica` 的原片采集、逐秒拆解和新角色提示词流程。输入是用户指定的短视频 URL；产物是本地深度灰视频、原音频、`原视频视频分镜细节.md`、复刻提示文档，以及 SkillTo.ai 上可视化的本人 Workflow 草稿。通用 MCP CRUD、素材上传、修订冲突与运行结果由 `skillto-int-workflow-mcp` 执行；先读其 `SKILL.md`，具体图结构读 [工作流节点合同](references/workflow-graph.md)；编辑各模型节点前读 [Prompt 格式规范](references/prompt-formats.md)，按其中模板替换真实引用并校验输出。

## 1. 取得原视频

保留原始 URL、视频 ID、作者、采集时间和授权范围。先读 `skillto-int`，按平台调用相应采集子技能；TikTok 使用 `skillto-int-tiktok-crawler` 核实公开视频和元数据。实际下载可用已安装的 `scrapling`/`scrapling-stream`；直链失败但公开播放器可正常播放时，可用复制来的 `scripts/capture_public_player.py` 保存播放器媒体响应。只处理获准访问的内容，不绕过登录、验证码、私密状态或 DRM。

每条原片单独存为工作目录的 `source.mp4`，记录出处和文件路径；时效签名 URL、Cookie、Token 不写进交付文档。用 `ffprobe` 核查时长、宽高、约分后的宽高比、帧率、音视频轨及可解码性；原片解码视频轨是最终视频画幅的依据，封面和播放器尺寸不能替代。页面标题和封面不能替代实际画面；无法取得原片就报告失败，不编造拆解。

## 2. 在本地生成深度灰视频并拆出音频

先完整读取已安装的 `$make-expression-depth-video` 技能说明，按其脚本从 `source.mp4` 在本地生成 `depth-gray.mp4`。该技能是本流程指定的深度生成步骤；未安装或运行失败时报告阻断，不换用普通灰度滤镜或其他方法冒充。单纯降饱和度或灰度滤镜不算深度灰。保持原时长、帧率、画幅、镜头硬切及人物运动，检查前/中/末帧、深浅方向、时间稳定性和可辨的脸部动作；用 `ffprobe` 回查深度片的时长、帧率和画幅，宽高比必须与原片一致。记录模型、参数及局限：这是相对深度，不是测量距离。若生成失败，不把普通灰度片标作成功的深度灰素材。

有音轨时用 `ffmpeg -i source.mp4 -map 0:a:0 -vn -c:a pcm_s16le audio.wav` 从原片提取音频，保留可核实的原始时间轴；无音轨则在索引中记为缺失，不合成假音频。分别用 `ffprobe` 回查深度片和音频时长，检查起始偏移及同步。所有媒体保存在工作目录，不写进 Skill 安装目录。深度片可以保留原音轨供本地预览；独立音频文件仍须交付。

## 3. 用原视频画面写分镜细节

完整观看原片；以半秒或更密的带时间戳原帧覆盖全长。`scripts/sample_timeline.py` 和 `scripts/make_contact.py` 可辅助抽帧及查候选切点，硬切须回看相邻原帧确认。区分镜头变化与角色运动，不因机位平移或景别渐变虚构 scene。

按 [结构化字段](references/analysis-schema.md) 写 `原视频视频分镜细节.md`：来源与媒体参数、采样与盲区、稳定角色 ID、连续 scene 时段、经确认的硬切点、逐秒画面表及证据帧。每个 `[n.00,min(n+1.00,片尾))` 区间分别记机位/景别/运镜/环境；每个在场角色分别记位置、姿态动作、表情口部、视线、神态和有依据的情绪推测。不可判或离屏直写，不靠标题、音乐或封面推断画面。可见事实与解释分栏；场景和秒段连续覆盖至片尾。独立音轨存在不等于已经听辨或转写。

## 4. 写新角色复刻提示文档

根据第 3 步写每条视频的 `深度灰视频复刻新角色prompt文档.md`，按 [提示文档合同](references/replica-prompt.md) 写整体概述、【新角色N】与【待替换角色N】对应、硬切点、逐秒动作和机位。替换目标优先用深度片可见的轮廓、层次、位置、遮挡与动作辨识，不能只靠原片颜色或服饰。新角色的物种或物体形态未知，不把原角色外貌强加给输入角色。完整证据始终保留在分镜细节文档；若 1000 字符提示长度与逐秒覆盖不能同时满足，报告冲突，不静默删除时段或伪称合格。

## 5. 在 SkillTo.ai 建立并校验 Workflow

先读 `skillto-int-workflow-mcp`，由它查询本人草稿、模型与 `workflow_get_node_options`，克隆一个本人源草稿并用稳定 UUID 编辑、校验。按 [工作流节点合同](references/workflow-graph.md)建立函数输入、逐角色多模态理解和角色卡生图、深度灰视频、场景图、分镜细节文本、全能参考 prompt、视频生成、函数输出节点及连线。第二角色可选：默认构建单角色图；用户确需第二角色时再增加其理解、角色卡和连线。只有服务端确实支持可选端口及条件执行，才在同一图中保留空的第二输入；缺失输入不能阻断单角色运行。每次保存使用最新 `draft_revision`，网页 `/drawing-workflow?wid=<workflow_uuid>` 读取同一草稿。

上传的只有通过本地检查的深度片、音频（如需且模型支持）、场景图和分镜文档等素材；用户新角色照片通过函数输入传入，不假设其内容。输入样例只在本地索引；正式运行时明确提交。模型、媒体数量、分辨率、比例和端口均以当前服务端可编辑目录和预检为准；不把不支持的组合强行保存为可运行图。用户指定的 GPT-Image 2.5、2k、26:9 逐项与实时 FMS 目录核对；`26:9` 不得自动改写成 `16:9`。任一项缺失时列出实际可选值并等待用户决定，不能只在提示词里写规格。角色卡宽高比与最终视频宽高比是两项独立要求；最终视频必须按原片画幅和所选视频模型能力核验。音频未接入最终视频时明确说明结果不保证原音轨同步。场景图由用户提供并上传；未提供时保留待补素材的草稿，不推断或合成场景。上传后回读深度片和场景图的素材 UUID，文本资源节点回读 `content` 正文的长度和首尾，确认画布真实引用了文件内容。视频节点必须实际消费深度片、角色卡、场景图和全能参考文本；模型不支持所需数量或格式时停止预检。

## 6. 运行与交付

建图本身不自动进行收费生成。用户授权真实运行后，经 `workflow_prepare_run` 复核节点、报价、预算和输入，再用稳定 `request_uuid` 调用 `workflow_start_run`；用 `workflow_get_run` 查到终态，返回真实的视频素材或可访问结果。失败时保留草稿与已有结果，不声称生成成功。交付本地四类文件（无音轨时说明）、工作流 UUID/网页链接、修订号、校验结果；运行过才交付任务状态和输出。维护 `workflow-index.json` 记录相对本地路径、SHA-256、远端素材 UUID、workflow UUID 与修订号，不存 Key 或临时凭据。
