# Skillto.ai工作台

Use this child for local Chrome extension installation, current-page video discovery/downloads, and the **拉片** workspace. It includes automatic same-origin workspace pairing (no user-entered port/token), browser-native progressive downloads with job-scoped import, yt-dlp/FFmpeg for explicitly selected manifests or page jobs, and a left-record/right-detail page with video playback, notes, timestamped shots and revision history. Installing the skill alone does not install the Chrome extension or prove a platform can be downloaded.

Read [installation and update steps](references/install.md) for setup or upgrades. Read [usage, contracts and troubleshooting](references/usage.md) for download or breakdown operations. Resolve every bundled resource from this loaded skill directory. Keep this child beside `skillto-int-table` and use its shared launcher service for normal operation; standalone mode is only for an explicitly selected standalone setup.

## Current product: Cat Catch based workbench

The user-verified discovery engine is the local Cat Catch fork. Keep the brand **SKillto.ai|工作台**, the redesigned welcome/consent page, and exactly two download destinations: **下载** and **同步到工作台**. The skill's `assets/cat-workbench/` overlay is the source of truth; `scripts/build_cat_extension.py --source <explicit-upstream> --destination <stable-runtime-directory>` applies it to the pinned Cat Catch source. Read `assets/cat-workbench/NOTICE.md`. Preserve upstream GPL attribution in credits and LICENSE. Do not replace the working discovery engine with the earlier experimental extractor.

The editor previews media, supports draggable start/end handles, numeric times and selection playback. For ordinary progressive files, full browser download works without the local service; a selected range uses local FFmpeg re-encoding for frame-accurate output. Explain that the full source may need downloading first. Current simplified range export does not support HLS/DASH manifest resources; display this explicitly instead of downloading a playlist as a video. Existing standalone manifest tools remain separate capabilities, not extra choices in this product UI.

Download-only clipped exports use the independent `exports` store and must not appear in breakdown records. Workbench sync uses the records/media store and preserves user notes. The Cat editor transfers selected source bytes in authenticated, ordered, bounded chunks directly to the shared local service; it does not depend on browser download paths. Keep the editor open during transfer. On successful processing, automatically open/focus the resulting breakdown, reusing an existing workspace tab when possible. Pair through an existing workspace page when available. Both use the same local table service and automatic same-origin pairing. The bridge sends selected media/source metadata, not Cat Catch's captured Cookie/Authorization cache. Keep selected media's ordinary Referer/Origin handling scoped to this extension and URL; do not bypass platform authentication, CAPTCHA, rate limits or DRM. Chrome installation/reload is a separate verification from copying files or testing an isolated browser.

The following current-page resolver details describe the earlier experimental `assets/extension` client; retain it only when explicitly requested, not as the default Cat Catch product.

## Workflow and boundaries

- Download only videos the user is authorized to save. The extension and link form require an explicit download-rights checkbox. A general download request does not authorize unrelated account crawling or private messages.
- The current-video action uses Chrome downloads, not a silent server-side page fallback. Scan in MAIN world, including shadow-root players and existing page state, and accept embedded media only when its aweme ID matches the open Douyin item. If passive state has no match, the explicit authorized download action may make one same-page detail request for that exact item using the page's existing session. Do not hook responses globally, export cookies, generate signatures, cycle identities, retry rejected requests, or choose unrelated preloaded resources. A denied/challenged/empty detail response stops this action with a fixed explanation. Respect restricted-account and DRM rules.
- Browser downloads request optional `downloads` permission directly from the button gesture. Chrome handles the selected media request and saves into its own `SkilltoWorkbench/` download folder. The local service imports only a new file matching that job's generated nonce/name, rejects arbitrary paths, links, invalid/partial media and oversized files, and preserves existing notes. Do not read or print unrelated browser downloads, cookies or credentials. The browser copy remains in Downloads; the workbench owns its independent imported copy.
- For explicitly requested server-side page jobs, prefer submitting the current canonical video page to yt-dlp for YouTube, TikTok, Douyin and Xiaohongshu. These are extractor integration targets, not a guarantee of current platform availability. When page parsing fails, the user can explicitly select a discovered MP4/HLS/DASH URL. Do not automatically cycle sessions, replay restricted requests or bypass DRM, login challenges, CAPTCHA, paywalls or rate limits. Live streams are outside this version's scope.
- Douyin modal_id/vid page links are normalized to single-video URLs. Explicit page scanning also reads existing Resource Timing media URL metadata for blob players; results can include preloaded videos and require manual selection. Fresh-cookie failures are reported explicitly; normalization and discovery do not resolve platform authentication requirements.
- Network discovery observes only tabs explicitly armed through **开启网络发现**, after the user grants optional site access. It captures URLs/MIME metadata, not response bodies or cookies. The explicit current-item resolver is a separate, bounded page-state/detail operation described above. Session-scoped resource URLs can contain temporary signatures; never print, export or log them. Do not add cookie-reading permissions as a silent fallback.
- No Chrome-profile credential extraction. An optional `SKILLTO_WORKBENCH_COOKIE_FILE` must identify the one user-selected authorized Netscape cookie file. Read the crawler's complete installed skill before configuring it, preserve its selected-session and restricted-account rules, and never use a restricted 小与AI session through this generic worker. A different filename is not permission to use a restricted identity. Challenges require the crawler's visible same-session manual handoff; this worker itself stops with a failed record.
- The crawler child retains account ownership checks, multi-cookie rules, request budgets and lineage for account/metric collection. Hand an explicitly requested video page to this child for downloading; a successful download does not establish account ownership or verify any metric. Do not change the crawler's existing authentication order.
- A downloaded video appears in **拉片** only after the worker has produced a nonempty media file. Verify record status and playback, then save notes through `/api/workbench/records`; use revision checking to avoid overwriting concurrent edits. The records are a separate SQLite store under the selected local table root, not ordinary table rows or remote AMD-PAD reports. Do not use table CRUD tools to imply this store was updated.
- Notes and shots are human-authored in this version. Do not claim ASR, automatic shot analysis, remote synchronization or automatic cookie reuse. For requested analysis, route to the media-analysis/ASR capabilities, then save evidence-based results through the workspace API.
- Keep runtime tokens, cookies, databases, videos and executables outside the skill/repository. Do not replace installed siblings wholesale; compare first and update only the intended integration files. The table and breakdowns share one launcher service; do not make users configure a parallel port. Automatic pairing uses the same-origin loopback content script and preserves the protected pairing endpoint. Attempt authorized Chrome installation/reload when controls are available; otherwise provide the precise blocker and the built-in installation page. An active service must restart to load Python changes; never stop another task's running downloads without checking their state.
