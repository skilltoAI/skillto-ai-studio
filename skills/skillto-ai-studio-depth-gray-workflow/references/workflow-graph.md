# SkillTo.ai 深度灰复刻 Workflow 节点合同

通用操作、认证、素材上传、修订和收费运行由 `skillto-ai-studio-workflow-mcp` 的 `SKILL.md` 规定。这里仅规定本复刻图的语义结构；真实节点类型、端口、模型 UUID、参数枚举从 `workflow_get_node_options` 和 `workflow_list_models` 查询，不能把这些中文标题当成接口常量。

```text
函数输入: 新角色1照片 ─→ 多模态理解1 ─┐
          └───────────→ 角色卡生图1 ──┤
函数输入: 新角色2照片(可选) → 理解2 ─┤
          └───────────→ 角色卡生图2 ──┤
分镜细节文本 ───────────────→ 全能参考prompt ─→ 视频生成 ─→ 函数输出: 视频
深度灰视频 ────────────────────────────→ 视频生成
场景图片 ──────────────────────────────→ 视频生成
```

没有第二角色照片时使用单角色草稿，省略理解2、生图2及相应连线；只有平台支持真正可选端口和条件执行，才将第二输入保留在同一草稿中，准备运行不得要求空值。原音频是单独交付素材；只有视频模型有音频输入且预检通过时才接入生成。否则输出视频不承诺携带原音轨。

## 节点职责

1. **函数输入**：`new_character_1_image` 必填，`new_character_2_image` 可选，均为图片。每次运行显式传本人上传的素材 UUID；本地样例不自动变成线上默认值。必要时提供场景图作为独立输入，但本流程默认使用用户提供的固定场景素材节点。
2. **新角色 N 多模态理解文本节点**：连入对应照片，选择当前确实支持图片理解的文本 FMS。用平台实际编译出的 `{{mixed_N}}` 引用令牌，不把字母 X 原样送出。提示词要求只输出可解析 JSON、键名恰为 `新角色名` 与 `新角色特征`；名称为恰好六个汉字的短称呼，特征不少于 80 个汉字，写可见的年龄阶段、颜色、种类/人种、肤色、毛发、四肢等适用特征和辨识细节。动物或物品的非适用字段不猜测、不硬填。校验 JSON、字数与照片对应关系；失败时先修正，不把无效文本传给下游。
各生成节点的可直接使用模板、占位符替换与输出检查见 [Prompt 格式规范](prompt-formats.md)。

3. **新角色 N 角色卡图片节点**：同时接入原照片和理解结果，要求忠实身份及三视图、表情图、统一深灰背景，不改物种和关键外貌。目标模型为用户指定的 GPT-Image 2.5，目标输出 2k、26:9；必须从模型目录选择真实可路由 FMS UUID，并用节点选项核验 2k 和 26:9 的精确枚举值。不能将 26:9 当作 16:9 或近似比例。若所选型号或比例不支持，列出可选值并请求用户决定，不能悄悄改比例或型号。
4. **深度灰视频素材节点**：上传本地 `depth-gray.mp4` 并绑定服务端返回的素材 UUID；校验时长、可读性、所有权，不上传普通灰度片充数。
5. **场景图片素材节点**：上传用户给出的新场景图；未提供时该输入标为缺失，建好草稿但不启动生成，不凭空选择场景。检查图像方向与原片画幅；若需要适配，只能经用户认可后按构图裁切或补边，不拉伸变形，也不把角色卡比例误作视频比例。
6. **原视频分镜细节文本节点**：导入 `原视频视频分镜细节.md` 的完整正文；`text_resource` 使用 `content: [fullText]`，保存后回读长度和首尾内容。文本正文是模型输入，文件名、节点标题或旧 `text` 字段不是正文；保持 scene、硬切、逐秒时间段和证据约束。
7. **全能参考 prompt 文本节点**：连接各新角色理解结果和分镜文本，生成面向视频模型的提示词。明确角色映射、深度灰控制、场景替换、服饰/动作/机位/硬切/节奏、与可用音轨的同步目标；不得虚构原片细节。依赖未完成时等待；不能引用空文本。
8. **视频生成与函数输出**：核心图使用一个视频生成节点，实际接入深度灰视频、每个角色卡、场景图和最终 prompt；选择当前能同时消费这些视频/图片/文本输入的 FMS，并核对输出比例、时长及规格。若任一连线在当前模型下不会进入真实请求，该图不得标为可运行。将完成后的视频素材作为函数输出，结果以服务端任务终态和素材 UUID 为准。额外模型分支仅在用户明确要求时添加，并单独预检及报价，不能因整图运行意外触发多个收费任务。

完整图在 SaaS 草稿中保存。用 `workflow_patch_node` 改节点内容，`workflow_save_draft` 改图，`workflow_validate_draft` 与 `workflow_prepare_run` 预检。运行之前检查实际请求确实包含已连接的文本、图片和视频，不能只在画布上连线而未送入模型。
