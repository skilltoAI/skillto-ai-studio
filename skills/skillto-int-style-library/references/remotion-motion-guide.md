<a id="selection"></a>
## 选型边界

先确定需要的动作和观察角度，再选成本合适的表示方式。风格、色系、内容、表示方式与动作独立建模。S008 的白模子形式可以采用其定义性的白色表面；其他材质与微缩沙盘仍使用项目指定的参数。

| 技术选项 | 适用能力 | 条件与局限 |
| --- | --- | --- |
| HTML + SVG | 文字、轮廓、图表、箭头、可编辑参数图形 | 真实三维厚度与表面变形需额外实现；复杂 SVG 滤镜需检查渲染负载 |
| 透明图片 + HTML/SVG 合成 | 纸纹、摄影、模型渲染图、部件剪贴 | 要有透明边缘与完整遮挡后素材；单图无法生成背面或变化的真实光照 |
| CSS 三维面片 | 有限折面、纸片翻转、层间视差 | 适合刚性平面与简单透视，不是布料/纸张物理解算器 |
| Three.js / React Three Fiber | 模型转身、绕拍、厚度、灯光、骨骼与网格 | 需要几何、材质和可控时间；浏览器/GPU 与服务器环境需要实际验证 |
| Canvas / PixiJS | 大量精灵、密集线条与纹理合成 | 独立控制保存在逻辑 ID/场景图中；需要渲染器时间适配，不直接等同 DOM 动画 |
| 预渲染透明部件／序列 | 复杂变形和材质的固定镜头 | 每个需要独立控制的对象应单独输出；整场视频无法保留内部元素编辑能力 |

Remotion 负责帧确定的视频编排与渲染；Motion 负责网页/交互的实时动画。可以共用资产、布局、构件参数和动作意图，分别实现时间适配器。不要把 Motion 默认的自主播放组件直接放进 Remotion 并假定离线导出一致。

<a id="contract"></a>
## 元素契约与分层

以下是建议的数据契约，不是 Remotion/Motion 自带 API，也不要求引入某个框架。即使元素不使用 DOM 渲染，也保留逻辑身份。

| 字段 | 用途 |
| --- | --- |
| id、parentId、styleId、variant | 稳定身份、父子关系、S 编号与原条目内的子形式 |
| kind、assetRef、sourceParts | 元素类型、素材引用与可编辑子部件；未取得素材时标明缺口 |
| bounds、anchor、depth、coordinateSpace | 尺寸、旋转/连接锚点、层级、所在坐标系 |
| material、paletteRef、contentRef | 材质、项目配色、项目内容分别引用；不把主题文字和参考配色写进样式定义 |
| start、duration、enter、idle、action、exit | 时间窗与各动画槽，idle 可为 hold；动作槽可以有多个命名动作 |
| maskRef、shadowRef、constraints | 裁切、投影、附着、接触、遮挡和端点绑定 |
| dataBinding、semanticId | 图表值、图例与标签关联，避免各处独立维护同一个数值 |
| seed、assetRevision | 可重现的纹理/手绘扰动、素材版本 |

推荐的控制层级：

```text
Scene / Camera
  Element：布局、身份、父子关系
    Lifecycle：入场 / 出场
      Idle：可关闭的驻留变化
        Surface：材质、裁切、表面内容
          Parts：关节、表情、折面等局部动作
  Connections：读取端点世界坐标
  Ground shadows：读取位置、高度与光照参数
  Overlay labels：按需要处于屏幕或场景坐标系
```

不要让入场、idle 与局部动作争写同一个 transform。它们可以各占一层，或先计算后合成为一个明确顺序的矩阵。地面阴影通常在接地平面上计算，不能简单复制物体旋转；连接线与文字可独立显现，但空间位置跟随关联对象。

<a id="timing"></a>
## 统一时间与动画生命周期

### Remotion

每个节点的局部时间由当前帧与起始帧计算。已经位于会偏移局部帧的时间容器内时，不再重复减起始帧。用 `useCurrentFrame()`、`interpolate()` 和 `spring()` 求属性；把入场、驻留、动作和出场区间显式记录。[动画属性](https://www.remotion.dev/docs/animating-properties)、[spring](https://www.remotion.dev/docs/spring)

`Sequence` 提供时间偏移和持续时间；当前文档也提供继承时间属性的组件与 `Interactive.create()`。按项目实际版本选用；不要为了套用新版接口强行升级已有工程。[时间容器与局部帧](https://www.remotion.dev/docs/sequence)

对于正数入场时长 I、出场时长 O、总时长 D（且 I + O ≤ D），可以将局部时间 t 的包络写为：

```text
enterProgress = clamp(t / I, 0, 1)
exitProgress  = clamp((t - (D - O)) / O, 0, 1)
opacity       = enterProgress * (1 - exitProgress)
idleOffset    = idleGate(t) * amplitude * sin(2π * frequency * t + phase)
```

这里是设计公式。`idleGate` 在入场末尾渐增、出场前渐减；阶段边界的初值和末值应相接。零时长阶段单独按瞬时状态处理，不能除零。若片段太短，先缩短或关闭 idle，而不是让入出场互相抢控制。

帧可被乱序或重复渲染，因此避免 `setTimeout`、独立 CSS animation、真实时间 `Date.now()` 和累加式位移驱动导出。随机纹理使用元素稳定 seed；有意逐步变化时由帧号派生，不在每次渲染重抽随机。[Remotion 时间约束](https://www.remotion.dev/docs/troubleshooting/css-animations)、[确定性 random](https://www.remotion.dev/docs/random)

### Motion

外层用 `initial` / `animate` / `exit` 管理生命周期，分组通过 `variants` 编排，idle 放在独立子层并根据当前阶段启停。`AnimatePresence` 应保留在组件树中直到退出完成；子元素使用稳定唯一 key，避免更换 key 意外重播全部元素。[React 动画](https://motion.dev/docs/react-animation)、[AnimatePresence](https://motion.dev/docs/react-animate-presence)

需要统一播放、暂停和定位时，可考虑 `animate()` 返回的控制对象与时间序列；实际适配仍需处理资源加载、状态恢复、循环和退出。自行驱动 Three/Canvas 参数时显式安排重绘，不假定修改值就自动生成视频帧。[animate 与播放控制](https://motion.dev/docs/animate)、[时间序列](https://motion.dev/docs/timeline-sequences)

同时支持交互和视频时，建议分别保存“场景初始状态”和带目标 ID、起止时间、参数及缓动的动作记录。拖动只是预览覆盖；用户结束拖动后再将动作落到记录中。时间轴定位时从初始状态和目标时间重建，先停止临时交互覆盖；视频导出只读取确定的动作记录。中途打断动作时记录当前求值结果作为新动作起点，避免隐含依赖某次网页操作历史。此协议是项目实现建议，不是 Motion 自带的录制功能。

### 两套驱动共用的动作设计

| 意图 | Remotion | Motion |
| --- | --- | --- |
| 入场 | 局部帧 → 插值或弹簧值 | initial → animate / variants |
| idle | 确定性的周期函数＋阶段包络 | 子层循环关键帧，阶段变化时收束或停用 |
| 局部动作 | 独立帧区间、关节曲线或缓存采样 | 状态或动作序列，避免覆盖父层动画 |
| 出场 | 时间窗内算完末帧，再停止呈现 | AnimatePresence + exit，完成后卸载 |
| 重排 | 从明确的起止布局插值 | 可用布局动画；精确视频交接另保存布局端点 |
| 定格节奏 | 对选定对象时间取阶梯采样 | 对选定对象使用分段关键帧；文字可继续稳定 |

<a id="t01"></a>
## T01 分层纸艺与遮挡

适用：S001；也可辅助 S004、S009。

1. 为每层创建独立 SVG/透明图片与深度参数；孔洞使用复合路径、mask 或 clipPath，引用 ID 保证唯一。
2. 背景净版覆盖所有可能暴露的范围。舞台框和前景遮挡单独放层，不与角色烘焙。
3. 小幅视差用每层不同位移系数；DOM 的 z-index 只管理遮挡顺序，不自动制造透视或厚度。
4. 表面纹理与纸片一起变换。层间阴影跟随距离变化；背光版本另设透光遮罩、光晕与遮光层。
5. Remotion 按帧更新位移/间距/光强；Motion 对各层独立驱动相同参数。入场顺序可以由深到浅，具体顺序由叙事决定。

升级条件：大角度旋转、侧面暴露、真实灯光穿透时改用 T06，不能无限放大二维视差。验收看前后穿帮、裁切边、移动后底板空洞和阴影脱离。

<a id="t02"></a>
## T02 拼贴、透明素材与材质

适用：S004、S005、S006；辅助 S007、S010、S011。

构件组织为纸/布/载体底形 → 附着纹理 → 独立图片裁切 → 可编辑文字 → 细节附件；投影放外层。图片用透明格式，保留足够边缘余量和正确 alpha，按画布位置保存锚点，避免自动裁边后跳位。

- 纸张粗边用 SVG mask 或独立边缘素材；真实揭纸还需要背面与 T03/T07。
- 票券伸长采用固定两端＋可变中段（或重算 SVG 轮廓），内容不随宽度拉伸。堆叠层作为实例，层数若编码数据就绑定同一数据源。
- 固定镜头下的模型素材应分别输出主体与可控制投影；不要把旧投影留在原底图产生双影。
- Remotion 由帧控制各构件，在所用版本的媒体组件加载完成后渲染；Motion 用独立 motion 容器控制生命周期，内部图片有自己的裁切/移动参数。
- 大量重复元素可改用 Canvas/Pixi，但保留逻辑 ID 和部件层级，不把整场合成图当作“全元素可编辑”。

验收看毛边白边、透明混合、纹理是否随对象移动、文字是否仍能改动、遮挡移走后内容是否完整。

<a id="t03"></a>
## T03 折面、翻页与简单立体书

适用：S002；可辅助 S004、S005。

每个刚性面片定义局部坐标、折线轴、正反面与父节点。简单面片用 perspective、preserve-3d 和合适的 transform-origin；多折面把角度关系写成同一进度参数的函数，避免相邻边断开。

Remotion 将开合进度映射到面片角度；Motion 用相同的角度参数和层级，机关由页角推导。旋转方向、正反面、裁切与投影单独检查。部分 CSS filter/overflow 组合会影响三维层叠，应把材质效果放在合适子层并验证实际浏览器结果。

曲面翻页、软纸卷曲与复杂机关改用细分网格和 T07；离线仿真可烘焙成可按时间定位的形态或序列。不能通过让一张整图左右翻转得到真实页背内容。

简单刚性单页可以由一个开合参数直接求页角；立体书的折撑、V 折或拉片仍须根据实际面片尺寸、折线和接点建立各自约束，不能通用地令所有面片转同一角度。没有机关源结构时，交接中明确需要补做结构设计。

<a id="t04"></a>
## T04 参数几何、浅浮雕与数据图形

适用：S006、S008、S009、S012。

先建立数据→尺度→形状的关系，再叠加美术材质。平面轮廓用 SVG；浅挤出可由正面、顶面、侧面构成，共用宽高和深度参数。数值、坐标轴、说明、图例分别独立，关联同一 semanticId。

长度变化时重算面片坐标、厚边和标签锚点，避免全组 scaleX 使文字、端帽、纸孔和倒角变形。凹印可用内阴影/遮罩近似；变化视角下的真实凹槽或倒角使用 T06。

Remotion 插值数据或显现进度并求几何；Motion 更新同一几何参数。采用 D3 时优先使用纯尺度/路径生成函数，不让 d3-transition 或自动模拟计时器绕过视频时钟。D3 的形状生成能力见 [d3-shape](https://d3js.org/d3-shape)。

验收看显示数值与几何是否一致、基线和量纲是否一致、透视是否扭曲比较、重复数量是否与实际口径对应。

<a id="t05"></a>
## T05 路径、箭头、笔迹与形状插值

适用：S003、S011、S012、S013、S014；其他风格的标注也可复用。

- 线条显示可设置总长度 L，以 strokeDasharray=L、strokeDashoffset=(1-p)L 实现进度 p；箭头头部独立，按进度显现或跟随当前路径末端。
- Motion 提供 pathLength、pathSpacing、pathOffset 等绘线控制；Remotion 则直接按帧求相应 SVG 属性。[Motion SVG 文档](https://motion.dev/docs/react-svg-animation)
- 具有粗细、飞白的笔刷需要真实填充轮廓与移动遮罩；仅给中心线添加描线效果不能完整还原笔迹。
- 孔洞、复合路径与形变需维护拓扑。路径指令兼容时可直接插值；差异大的形状可评估 Flubber，必须检查中间帧自交、孔洞和轮廓方向。[Flubber 项目](https://github.com/veltman/flubber)
- 手绘标记可评估 Rough.js 的 SVG/Canvas 图形生成；固定 seed 与采样参数，生成后保留可控路径，不能每次渲染重新抖动。[Rough.js](https://roughjs.com/)
- 引线锚点转换到同一坐标系后再求路径。显示与运动分开管理，避免目标移动而箭头留在旧位置。

中文书写需要字形笔顺或逐笔路径数据；只有字体轮廓不能恢复正确笔顺。密集线条、针脚或小字号应在最终输出尺寸验收。

<a id="t06"></a>
## T06 三维模型、空间、灯光与相机

适用：S007、S008、S009、S010；支持其他条目的真实厚度与观察角度变化。

对象保持独立 mesh/group，保留 pivot、材质、贴图、骨骼与命名节点。可从已有 glTF/GLB 导入或在获授权制作任务中建模；查询本库不会自动获得模型。白模子形式使用白色/近白与低纹理材质体现体块，粗糙度、阴影和灯光仍需设计；沙盘其他子形式按项目选材。

Remotion 可用 @remotion/three 的 ThreeCanvas 承载 R3F 场景，模型、相机和灯光以 useCurrentFrame 绝对定位；不要让普通 R3F useFrame 的累加 delta 成为导出时钟。[ThreeCanvas](https://www.remotion.dev/docs/three-canvas)

Motion 网页实现可让 Three/R3F 承担绘制、Motion 控制相关数值或参数并触发重绘；具体桥接以项目版本为准，不假定存在通用的 motion.mesh。已有动作可使用 Three AnimationMixer 的时间定位能力，但必须配置动作并验证回跳、重复取样和循环边界。[AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)

投影、接触阴影、环境光、透明层排序与贴图加载是独立检查项。大量相同对象可以实例化但保留逻辑 ID。若用预渲染序列降低运行成本，每个需要独立控制的对象分别输出，并明确固定机位和内部动作范围。

<a id="t07"></a>
## T07 柔性表面、材质形变与预制动画

适用：S002、S010、S011；纸片翘角等可复用。

轻微起伏可以使用细分网格的局部位移、形态键或经过验证的位移滤镜；保持锚点不动，并让纹理跟随局部 UV。布料与纸张要区别刚度、边缘和褶皱，黏土要考虑体积与部件连续性。仅增加一张材质贴图不会获得这些结构。

Remotion 对顶点、骨骼或形态权重按帧取样；Motion 对同一参数进行实时插值。真正的布料、碰撞、撕裂或揉捏可在外部建模/仿真流程预制，但应保留按时间定位的缓存、骨骼或序列；不能把上一帧状态当作下一帧必须存在的前提。

纯位图近似应明确只支持局部变形，检查裁切边和纹理拉伸。定格外观可只对对象动作阶梯采样，画布、文字和字幕不必一起降频。

<a id="t08"></a>
## T08 部件层级、关节与表情

适用：S003、S007、S010。

先区分整体移动、关节动作、表情切换与自然网格变形。二维纸偶用 SVG g 或透明部件建立父子树；关节 pivot 放在接点并预留覆盖，持握道具绑定手部，脚/支点可通过约束或补偿保持接触。五官和嘴形需要独立素材。

Remotion 各节点按局部帧求旋转、位置和表情索引；Motion 各层使用独立 variants 或动作状态，整体出场可收束正在进行的局部动作。不要以整个人物拉伸代替所有呼吸或以横向镜像代替完整转身。

已有 Lottie/Rive 资产可作为选项，但需要确认资产暴露的层、动作或状态输入。导出的单个动画文件不必然提供外部任意部件控制；可按对象分别导出或回源重做。Remotion 已提供对应接入包，实际功能以所用版本和资产为准。[Lottie](https://www.remotion.dev/docs/lottie/lottie)、[Rive](https://www.remotion.dev/docs/rive)

<a id="t09"></a>
## T09 字体、图片容器、标签与图例

适用：全部条目，尤其 S004、S005、S013、S014。

文字尽量保持为可编辑 HTML/SVG 文本；需要精确字形轮廓才转路径。图像内容、纸框、标题和注释各有节点；样式参数不包含具体文案。根据字形整形、标点和阅读顺序分割文字，不用简单字符串切分破坏组合字符。

字体文件、字重与字距加载完成后再测量排版；为数字变化和不同长度文本保留空间。三维标签明确选择世界坐标（跟随模型）还是屏幕坐标（阅读优先），引线投影到相同坐标系。

曲面纸张上的文字可在字体就绪后排版到 Canvas/SVG，再更新成随网格 UV 变形的纹理；原始文字、段落和独立动画参数仍保存在节点数据中，不能只留下烘焙后的图片。每帧需要变化的文字先求本帧状态、绘制纹理，再提交三维帧；异步生成纹理时纳入资源完成屏障。保留页正反面各自排版、行距与足够纹理分辨率；如果文字必须有独立遮挡或离开纸面，使用独立网格/图层而非仅合成进整页纹理。

Remotion 按帧计算每词/每字进度和布局插值；Motion 可使用独立节点、variants 或布局动画。笔画书写走 T05，实体字块走 T06。图例的符号、底板与文字可各自动画，但保留与数据图形的语义绑定；不要凭变色就认定状态已被清楚表达。

## 各类元素的实现与验收

| 元素 | 实现方法 | 必须保留的独立能力 |
| --- | --- | --- |
| 场景与背景 | 底材、远中近景、前景遮挡分离，移动暴露区有净版 | 各可动对象可分别进出，背景可保持静止 |
| 角色 | 透明整体、部件树、骨骼或网格按动作粒度选择 | 整体生命周期与头部、五官、四肢等局部动作分开 |
| 道具 | 主体、铰接部件、表面图案、支点与投影 | 贴图随物体；被持握时跟随手，仍可局部动作 |
| 图片 | 图像内容与纸框/裁切/阴影分离 | 图片内部移动与外框入场互不覆盖 |
| 文字 | 原生排版或字形路径；加载字体后测量 | 标题、正文、注解分别控制，不烘焙进图片 |
| 数字与图表 | 共享数据源生成值与几何 | 数值、几何、轴、辅助标记独立，同时保持语义一致 |
| 箭头与连接线 | 路径、头部、标签，端点绑定目标坐标 | 绘制进度独立于端点运动，目标变化时不断连 |
| 图例与标牌 | 符号、文字、底板独立，semanticId 关联 | 可分项强调，也可作为一组移动和退出 |
| 笔迹与批注 | 轮廓/纹理＋揭示遮罩，必要时保存笔顺 | 显现、位置、强调分别控制，不把笔迹压入背景 |
| 纸布边缘与纹理 | 局部 mask、UV 或附着子层，稳定 seed | 随本体运动，无随机闪烁；形变时不出现外部纹理滑动 |
| 阴影 | 轮廓阴影、接触阴影、地面投影区别处理 | 主体离地/旋转时参数一致；主体退出后无残留 |
| 灯光与光晕 | 可控渐变/遮罩或三维光源 | 位置、强度、显隐独立，遮挡关系与物体一致 |

## 实施交接与验证

交接时给出：S 编号与子形式、T 路线、素材清单及缺口、节点 ID/锚点/父子关系、入场/idle/动作/出场时间、依赖版本、采用的参考项目和验证结果。配色与内容放在独立项目参数中；白模子形式的白色作为其形式特征单独说明。

验证直接围绕用户可见能力：

1. **独立性**：分别隐藏、替换、移动每类元素；文字、箭头和图例不能被烘焙到背景而无法控制。
2. **结构**：检查动作极值、遮挡移除、页背、关节接缝、接地与投影；确认真实三维需求没有被平面翻转替代。
3. **时间**：抽查入场末、idle 中、出场末；对同一帧重复取样、乱序定位与回跳，状态应一致。实时交互另外检查中途退出与打断。
4. **内容参数**：替换不同长度文字和数据，确认排版、端帽、数值/图形与连接线仍正确；换配色不应改变类别。白模若更改其定义性表面表现，应准确称为相应其他模型子形式，而非硬说外观完全未变。
5. **输出**：按目标尺寸检查线条、文字和边缘，比较实际渲染与预览；记录已验证能力与仍为设计建议的部分。只做查询时无需安装运行全部技术选项。

本技能本身不发布网页、不提交生成任务、不自动执行示例项目；这些动作属于用户明确提出的后续制作任务。Studio `.motion` 模板的检查和运行仍使用 `skillto-int-motion` 的已验证适配器与边界。
