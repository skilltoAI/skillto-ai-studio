# 风格库录入规范

适用于新增、补充、修订、去重与合并风格条目。配合 [技能流程](../SKILL.md)、[检索索引](style-index.md)、[风格明细](style-details.md) 与 [技术指南](remotion-motion-guide.md) 使用。本规范不新增风格；当前目录仍为 S001–S014。

## 1. 什么可以录入

本库收录“模块化分层视觉设计”下可复用的美术风格与表现手法。分类依据是造型、轮廓、材质表现、制作构造、空间组织与图形语言；“可拆解、可独立动画”是共同的制作要求，不单独作为一个新风格。

录入判断：换成另一套题材、对象和文案后，条目的主要视觉规则仍应成立。风格应能解释“为什么长这样、如何组织构件”，而不只描述某张画面有什么。

| 输入变化 | 处理方式 |
| --- | --- |
| 只换一般色系、主体身份、物品、文字、数据或行业 | 沿用已有风格，变化写入项目参数 |
| 同一手法的不同称谓、中英别名 | 并入已有条目的别名 |
| 基础构造相同，只增加局部工艺或表现特征 | 优先记为已有条目的子形式，如纸剧场的背光形式 |
| 混合两种已有手法 | 记录主风格＋辅助手法及原编号，不因组合自动新增 |
| 仅换 SVG、图片、Three.js 或动画库 | 更新技术选项，不新增美术风格 |
| 仅采用淡入、弹跳、缩放、视差、定格节奏等通用动作 | 写入动效方法，不独立建类 |
| 造型、材质、构造或图形语言有稳定可区分的规则 | 对比最近条目；用户已要求新增时才分配新编号 |

不要求条目互斥。相近条目应说明主导特征及区别；使用工作命名时注明“库内描述性名称”，不虚构行业公认或美术史流派地位。索引与别名均查过仍无法判断时，只澄清影响分类的关键歧义。

## 2. 色系与具体内容的边界

- **一般配色保持开放**：参考中的纸张颜色、强调色、背景色、摄影去色与字体颜色不自动成为风格要求。
- **形式固有特征可以明确**：白模的白色或近白、低纹理表面是该子形式的识别特征，可以提及。说明适用的子形式范围，不扩展为全库或同条目其他子形式的统一要求。
- **具体内容保持开放**：不把参考中的人物身份、道具种类、行业、品牌、年份、指标、文案或结论写入条目定义。必要示例只用于解释手法，明确可替换。
- **适用场景使用抽象需求**：写比较、分类、结构拆解、流程、因果、证据组织、空间揭示、关系网络、情绪表达等；具体题材可以在当前项目中匹配这些需求。

例如，“米白纸张、朱红下划线、展示招聘统计”应抽象为“纸本层次、可独立批注、适合证据组织或数量比较”；“白模”保留白色表面特征，但不把主体锁定为建筑。不能为了避开颜色限制而删掉一个形式的定义性特征。

## 3. 编号、命名与查重

- 用 `S` 加至少三位数字作为稳定编号。现有编号不重排、不复用；新增时在历史已用最大号之后递增，不填补已退役编号。
- 名称采用美术形式或手法名称；内容标签、配色昵称与渲染库名称不作为主名称。
- 修改名称时保持编号，旧称在有检索价值时保留为别名；子形式不另分配编号。
- 查重至少对照主名、别名、构造与最近条目的区别。只把尚未出现的名称当作新风格不足以通过查重。
- 合并或退役仅在用户请求范围内进行；已有编号保留迁移说明和指向，不静默改写旧编号含义。同步索引与技术映射，使旧编号仍可追溯。
- T 编号代表技术路线，P 编号代表参考入口，两者与 S 风格编号分别维护。能复用已有技术路线就复用，风格数量不要求与技术路线数量相同。

## 4. 明细库字段与模板

以下字段与现有明细格式一致。信息不足时明确所缺素材或待核查项，不以猜测填满；必须能说明本项的识别规则、相近项区别与独立动画方案，才作为完整条目交付。没有实际源资产时写“建议拆解”，不写“已经具备分层”。

```markdown
<a id="sNNN"></a>
## SNNN 风格名称

- **别名**：检索别名、中英名称；需要时注明库内描述性名称。
- **美术特点**：可识别且能跨题材复用的视觉规则；固有特征的适用范围。
- **空间与构件**：2D、2.5D 或 3D 选择；各类独立构件与必要子部件。
- **拆解方法**：轮廓/面片/关节/几何如何拆；父子、锚点、遮挡、连接、材质附着和素材补全。
- **入场**：符合材料与构造的可选动作。
- **idle／独立动作**：可选驻留变化、局部表演与联动约束；允许静止保持。
- **出场**：可选离场、收束与状态复原方法。
- **适用场景**：用分号列出抽象表达需求，直接同步到索引。
- **限制与区别**：最近风格区别；素材与动作粒度限制；必要时标注推断。
- **技术入口**：链接技术指南中的现有或新增 T 路线。
```

有新命名、真实工艺或参考来源需要交代时，可追加“识别依据／来源”字段：记录用户文字、可见图像证据或可核查的文献链接，区分观察与推断。通用方法的整理不强制凑引用；不把单图外观推断成真实制作工艺、已有模型、骨骼或图层。

## 5. 元素拆解与动画要求

按风格所需列出角色、道具、场景分区、图片、文字、数字/图表、箭头、图例，以及表面纹理、阴影、灯光等构件。并非每个设计必须出现所有元素，但实际出现且需要独立动画的对象不能被烘焙成无法控制的整图。

每个构件应有稳定身份、布局、层级和时间窗口，支持入场、idle、局部动作、出场。独立控制与必要联动同时成立：标签随主体、箭头跟端点、脚部保持接地、纹理附着物体，子部件仍可独立编排。

| 动作粒度 | 需要的结构或素材 | 不能据此宣称的能力 |
| --- | --- | --- |
| 整体移动 | 独立透明对象或可编辑形状 | 自然眨眼、摆手、转身 |
| 部件动作 | 分件、关节、表情或骨骼，覆盖余量和锚点 | 任意柔性变形、未准备的背面 |
| 表面形变 | 网格、UV、形态键、可定位缓存或足够的序列 | 无需额外素材的任意机位与拓扑变化 |
| 真实转身或绕拍 | 完整三维或经验证可满足角度范围的多视图 | 超出已有几何、视图或光照范围的表现 |

记录干净底板、遮挡后区域、正反面、独立投影和可编辑文字的需求。idle 可保持静止；动效描述使用可选语汇，避免全画面无理由持续晃动。入场、驻留和离场的状态应能衔接。

## 6. 技术指南的录入要求

在技术指南的逐风格映射表中，同步 S 编号与名称，并补齐：

| 字段 | 录入要求 |
| --- | --- |
| 构件与素材 | 需要哪些源文件、层、网格、关节、字体、纹理、净版；哪些尚缺 |
| Remotion 方法 | 可按目标帧求值的路线；时间窗、几何/参数驱动与资源加载方法 |
| Motion 方法 | 网页实时的节点、状态与入出场路线；如需视频说明时间适配需求 |
| 技术选项与限制 | SVG、透明图片、CSS 面片、三维、预渲染的取舍；简化近似明确标注 |
| 中间件与依赖 | 只列实际有用的可选项、用途与接入条件；发现宿主能力，不声称随技能已安装 |
| 参考项目 | 可追溯的官方/维护方链接、可借鉴部分、仍需补齐部分；无合适项目就如实说明 |
| 验证状态 | 文档核查日期；实际运行时再记录版本、环境、验证能力及结果 |

“Remotion 可实现”和“Motion 可实现”必须说明动作粒度与路线。若某一路线有条件或不适用，说明具体限制，不强求两个框架实现相同功能。不能把 Motion 与 Studio 的 `.motion` 模板系统混为一谈。

新增外部技术选项先核查当前官方文档或项目来源；不要凭记忆编造包名、API、示例地址、兼容性或许可。“链接可查”不等于“依赖已安装”，“工程示例”不等于“本风格现成模板”，“设计方案”不等于“已渲染验证”。单纯录入无需运行全部参考项目或进行收费生成。

## 7. 三份库文档的同步与检查

维护顺序是明细 → 索引 → 技术映射；本规范作为第四份参考文档承载录入规则，不混入检索索引。

1. **明细**：字段齐全、区别明确，固有特征与项目变量范围准确，动作粒度与源素材相符。
2. **索引**：仍然只含“序号、风格名称、适用场景”三列；主名、编号和适用场景与明细一致，不混入配色、案例或技术说明。
3. **技术映射**：每个有效编号有对应行和可定位的 T 路线；新项目/中间件有来源与验证层级，已用编号保留追溯关系。
4. **范围说明**：只有实际新增/退役时更新技能入口、库标题、数量、编号范围、家族汇总，以及父技能/清单中涉及数量与能力的说明。本次仅制定规范，14 类保持原样。
5. **链接与分发**：相对路径、锚点有效，名称与编号没有冲突；文档为 UTF-8/LF，不把用户素材、密钥、运行状态放入技能包。按仓库现有规则校验。
6. **查询复核**：用本次条目的抽象需求检查是否能检索到；换一组非定义性配色与内容仍能适用；检查白模等固有特征没有被误删或扩大约束范围。

交付报告简要写明本次属于新增、别名、子形式还是修改，受影响编号和文件、校验结果、实际验证状态及必要素材缺口。默认继续保持现有范围；只有明确的扩库请求才新增条目，不因制定规范、看到参考图或讨论可能风格自动扩库。
