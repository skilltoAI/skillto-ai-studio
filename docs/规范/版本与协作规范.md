# 版本与协作规范

适用触发：每次任务必读。路径提示：`**`。多个命中必须累加读取。

状态：STASS 迁移目标约束，不代表对应功能已经实现或验收。

- 遵循 AGENTS.md 的 CODEUP_FETCH_* / CODEUP_PUSH_* 分离契约和 CONTRIBUTING.md；使用 codeup_git.py，不跨方向回退凭据。每48小时成功同步一次，只有集成远端基线后才记录成功时间。

- 所有完成的逻辑变更写入唯一 CHANGELOG.md 的 Unreleased：日期、编号、范围、摘要、验证、规范更新和兼容性影响。检查通过后按具体路径本地提交到 codex/*，不混入其他任务改动。

- 接口、架构、数据、权限、交互、部署或验收变更同步更新相关规范；只有路由或全局原则变化才改总索引。普通修复无需机械改规范，但必须记录判断。

- 推送、合并主分支、标签和发布需明确授权。真实数据、凭据、EXE和迁移报告不进 Git。
- GitHub 推送使用独立远端 `github`，指向 `https://github.com/skilltoAI/skillto-ai-studio.git`。保留已有 `origin` 和 `codeup`，提交前核对实际 push URL 和目标分支。
- Windows Git for Windows 通过 Git Credential Manager（GCM）使用 Windows 凭据管理器保存的 GitHub OAuth 登录。同一 Windows 用户可复用已授权的匹配账号，账号须具有目标仓库写权限。Git 提交作者 `user.name`、`user.email` 由本地 Git 配置提供，独立于 GCM 登录身份。
- 凭据缺失或失效时通过 GCM 浏览器授权；不复制其他仓库的 Git 配置，不将 GitHub 令牌写入 URL、命令、项目环境文件或日志，不用 `CODEUP_*` 认证 GitHub。只读探测不能证明写权限。
- 首次向公开仓库推送前检查目标提交可达的全部历史、凭据、真实数据、内部素材及再分发范围。确认范围并获授权后显式推送指定分支，完成后用远端引用核对 SHA。命令见仓库根 `CONTRIBUTING.md` 的「发布到 GitHub」。

- 多工具使用独立工作树/分支，源码拉新不得直接更新已安装程序或业务数据。运行版本切换遵循[版本与数据一致性规范](版本与数据一致性规范.md)，不由各宿主独立git pull运行目录。
